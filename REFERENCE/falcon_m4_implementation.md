# Falcon Cortex-M4 논문: 최적화 범위·구현 방식·원리

대상은 Thomas Pornin의 **「Falcon on ARM Cortex-M4: an Update」(2025-01-29)**다.
저장된 [논문 PDF](falcon_m4.pdf)와 [공식 ePrint](https://eprint.iacr.org/2025/123)를 확인했다.
아래는 **2025년 논문 내용**을 중심으로 요약하고, 현재 `fn-dsa_m4/ref`에서 추가된 내용은 마지막에 구분했다.

## 1. 먼저 큰 그림

핵심은 **전체 알고리즘을 어셈블리로 다시 쓰는 것이 아니라, C로 작성한 상위 과정에서 자주 호출하는 연산을 M4에 맞게 구현하는 것**이다.
MVE나 FP32 벡터 인트린직을 이용한 논문이 아니다.

| 단계 | 어느 부분을 최적화했나? | 구현 방식 | 핵심 원리 |
|---|---|---|---|
| 키 생성 | NTRU solver의 메모리·근사 계산 | 주로 C, 기존 `ntrugen` 구현 재사용 | 작업 버퍼 재사용·배치 개선, 부동소수점 대신 64비트 고정소수점 사용 |
| 키 생성 | 작은 소수 p에서의 반으로 나누기·Montgomery 곱셈, 고정소수점 곱셈·제곱 | **C 안의 인라인 어셈블리** | M4의 32×32→64 곱셈·누산 명령으로 명령 수와 자리올림 처리 비용 감소 |
| 서명 | FP64 변환·덧셈·곱셈·나눗셈·제곱근, 합과 차 동시 계산 | **별도 `.s` 어셈블리 함수** + 일부 인라인 호출부 | binary64를 정수 비트열로 유지하면서 정렬·정규화·반올림을 효율적으로 수행 |
| 서명 | FFT/iFFT, Gram matrix, LDL, ffSampling | 논문 시점에는 **주로 C**에서 위 연산 함수를 호출 | 특히 FFT의 `x+y`, `x-y` 계산에 공통 작업 재사용; 하위 연산 개선이 상위 함수에 전파 |
| 서명 | Gaussian 기본 샘플러·지수함수 근사 계산 | C + 별도 어셈블리 + 인라인 어셈블리 | 임계값 비교를 분기 없이 처리하고, 고정소수점 다항식 평가에 긴 곱셈 명령 활용 |
| 검증 | SHAKE/Keccak-f | **별도 `.s` 어셈블리 함수** | 64비트 상태를 홀수·짝수 위치 비트로 분리해 32비트 회전·논리 연산으로 처리 |
| 검증 | q=12289 NTT/iNTT·다항식 연산·디코딩 | **별도 `.s` 어셈블리 함수** + C 상위 검증 흐름 | Montgomery 축약, 한 레지스터의 두 16비트 계수에 DSP 병렬 연산, 메모리 접근 감소 |

Gaussian 세부 구현은 논문 §2.4의 주된 설명인 FP64 최적화에 더해, 당시 공개 소스에서 확인한 내용이다. 새로운 Gaussian 분포 자체를 제안한 것으로 해석하면 안 된다.

## 2. 키 생성: 고정소수점 + 네 가지 인라인 어셈블리

논문 §2.3(pp. 9–10)은 `ntrugen`의 메모리 절약형 키 생성 구현을 가져왔다고 설명한다.
NTRU solver 전체를 어셈블리화한 것이 아니다. FFT가 필요한 근사 계산은 **정수부 32비트 + 소수부 32비트인 64비트 고정소수점**으로 수행한다.
서명의 binary64 에뮬레이션과는 서로 다른 수 표현이다.

| 함수 | 사용 위치·역할 | 구현 원리 |
|---|---|---|
| `mp_half()` | 작은 소수 p를 사용하는 모듈러 연산 | `(x + (x가 홀수이면 p, 아니면 0))/2`. `UBFX → UMLAL → LSR`로 조건부 보정을 분기 없이 수행한다. 논문의 예에서는 4명령을 3명령으로 줄인다. |
| `mp_mmul()` | RNS/작은 소수 NTT 등에서의 Montgomery 곱셈 | `UMULL`, `MUL`, `UMLAL`로 곱과 축약을 결합하고, 결과 범위 보정을 마스크로 처리한다. 일반 정수 나눗셈을 사용하지 않는다. |
| `fxr_mul()` | 고정소수점 FFT 등 | 두 입력을 32비트 정수 워드로 나눠 부분곱을 만들고 누산한다. 고정소수점 결과에 필요한 비트 구간과 부호 보정을 직접 계산한다. |
| `fxr_sqr()` | 고정소수점 제곱 | 같은 입력의 부분곱 구조를 이용하는 전용 구현이다. 서명용 `fpr_sqr()`와 이름·표현 방식이 다르다. |

코드 위치: [kgen_inner.h](../fn-dsa_m4/ref/kgen_inner.h), [kgen_fxp.c](../fn-dsa_m4/ref/kgen_fxp.c), [kgen_ntru.c](../fn-dsa_m4/ref/kgen_ntru.c).
`FNDSA_ASM_CORTEXM4=1`일 때 해당 인라인 어셈블리 분기가 선택된다.

## 3. 서명: FP64 의미를 유지한 정수 어셈블리

M4의 FPU는 FP32만 지원하므로, 논문은 FP64 값을 `uint64_t`에 **binary64 비트 패턴 그대로** 보관한다.
연산할 때 부호·지수·가수를 처리하고 binary64의 최근접 짝수 반올림(`roundTiesToEven`)을 재현한다.
따라서 **FP64를 두 개의 FP32 부동소수점 값으로 바꾼 것이 아니다.** 32비트 정수 레지스터 두 개를 사용하는 것과 FP32 연산은 다르다.
Falcon에서 발생하지 않는 NaN·무한대·비정규값·오버플로·언더플로 처리는 전제로 제외하므로, 범용 IEEE 754 라이브러리 전체를 구현한 것도 아니다. (논문 §2.4, pp. 10–14)

| 논문에서 최적화한 연산 | 방식·원리 |
|---|---|
| `fpr_scaled` | 정수와 스케일을 binary64로 변환. 선행 0 개수와 시프트를 이용해 가수·지수를 구성한다. |
| `fpr_add` / 뺄셈 | 지수 차이만큼 가수를 정렬하고, 합·차를 정규화·반올림한다. 비밀값에 따른 시프트도 분기 없이 처리하며 `CLZ`, `UMULL`, `UMLAL` 등을 활용한다. 뺄셈은 입력 부호 반전 후 같은 루틴을 쓴다. |
| `fpr_add_sub` | `x+y`와 `x-y`에서 **입력 가수 정렬을 한 번만** 한다. 결과 정규화는 각각 필요하다. 두 64비트 결과를 레지스터로 받는 인라인 어셈블리 호출부로 구조체 반환·메모리 저장 비용도 피한다. |
| `fpr_mul` | 가수의 정수 부분곱을 긴 곱셈·누산으로 계산한다. 논문은 64×64→128 정수 곱을 `UMULL` 2개와 `UMAAL` 2개로 처리하는 예를 설명한다. |
| `fpr_div`, `fpr_sqrt` | FP64 나눗셈·제곱근을 전용 정수 어셈블리로 구현한다. 비밀값에 가변 시간 하드웨어 정수 나눗셈을 적용하지 않는다. 논문은 이 두 루틴의 내부 알고리즘을 세부적으로 전개하지는 않는다. |
| 공통 반올림 | 버려지는 비트·sticky bit·남는 최하위 비트를 이용한다. 조건 분기 대신 비트 배치와 덧셈의 carry를 결과에 전파한다. |

논문 Table 2의 루틴 비용은 순서대로 34, 80, 100, 45, 458, 610 cycles다.
이는 **논문 시점의 개별 루틴 수치**이며 호출자의 인수 준비·`BL` 비용 등은 제외된다. 최신 코드의 측정값이나 FFT 전체 비용으로 사용하면 안 된다.

코드 위치: [sign_fpr_cm4.s](../fn-dsa_m4/ref/sign_fpr_cm4.s), [sign_inner.h](../fn-dsa_m4/ref/sign_inner.h), [sign_fpoly.c](../fn-dsa_m4/ref/sign_fpoly.c).
예를 들어 `FFT의 C 반복문 → fpr_add_sub/fpr_mul → M4 어셈블리` 형태이므로, 하위 함수를 빠르게 하면 이를 사용하는 FFT·LDL·ffSampling·서명도 빨라진다. 다만 해당 함수를 호출하지 않는 부분까지 개선되는 것은 아니다.

Gaussian 관련 공개 코드에서는 기본 half-Gaussian 샘플러가 임계값들을 고정된 순서로 비교한다.
`BerExp`에서 사용하는 `expm_p63()`는 FACCT에서 가져온 계수로 지수함수를 다항식 근사하며, 정수·고정소수점 부분곱에 인라인 어셈블리를 사용한다.
코드 위치: [sign_sampler.c](../fn-dsa_m4/ref/sign_sampler.c), [sign_sampler_cm4.s](../fn-dsa_m4/ref/sign_sampler_cm4.s).

## 4. 검증: 정수 DSP와 해시 최적화

검증에는 서명과 같은 FP64 FFT가 필요하지 않는다. 주요 경로는 디코딩, SHAKE/Hash-to-Point, q=12289 다항식 연산·NTT, norm 검사다. (논문 §2.5, pp. 15–17)

| 대상 | 방식·원리 | 코드 |
|---|---|---|
| Keccak-f | 각 64비트 상태의 짝수 비트와 홀수 비트를 각각 32비트 워드로 모은다. 64비트 회전을 32비트 회전·워드 교환으로 바꾸고, ARM의 회전이 결합된 논리 명령을 활용한다. permutation 입·출구에서만 비트 분리·결합해 외부 SHAKE 상태는 일반 바이트 버퍼로 사용할 수 있게 한다. | [sha3_cm4.s](../fn-dsa_m4/ref/sha3_cm4.s) |
| Montgomery 축약 | 내부 표현을 `[0,q]`까지 허용해 0과 q 모두 0을 나타내게 한다. `MUL + UMAAL`의 두 명령으로 32비트 값의 Montgomery 축약을 수행한다. | [mq_cm4.s](../fn-dsa_m4/ref/mq_cm4.s) |
| 다항식 계수 연산 | 32비트 레지스터에 두 16비트 계수를 담는다. `SADD16`, `SSUB16`, `SEL`로 두 모듈러 덧셈·뺄셈을 병렬 처리하고, `SMULBB` 등으로 halfword 곱셈을 한다. **M4 DSP 명령이지 MVE가 아니다.** | [mq_cm4.s](../fn-dsa_m4/ref/mq_cm4.s) |
| NTT/iNTT | 위 모듈러 연산을 butterfly에 적용한 별도 어셈블리 루틴. 완전한 루프 펼치기보다 코드 크기를 중시한다. 논문은 자기 NTT가 다른 선행연구의 NTT보다 빠르다고 주장하지 않는다. | [mq_cm4.s](../fn-dsa_m4/ref/mq_cm4.s) |
| 공개키·서명 디코딩 | 비트 추출·정수 범위 검사·메모리 접근을 어셈블리로 처리한다. 논문은 기존 연구 대비 검증 개선에 이런 보조 연산도 크게 기여한다고 설명한다. | [codec_cm4.s](../fn-dsa_m4/ref/codec_cm4.s) |

논문 시점의 검증은 NTT 2회 + iNTT 1회를 사용한다. 공개키 NTT와 공개키 해시를 여러 검증 사이에 캐싱하는 방법은 논문에서 **가능한 추가 최적화**로 설명하지만, 보고한 기본 API에는 적용하지 않았다.

## 5. 공통 기법과 구현 방식 정리

- **메모리·명령 스케줄링:** 의존성이 없는 `LDR`를 묶고 `STR`를 계산과 배치해 파이프라인·store buffer를 활용한다. 메모리 접근이 많은 어셈블리에서는 32비트 명령 정렬도 신경 쓴다. 작업 버퍼는 32바이트 정렬한다. (논문 §2.2)
- **FPU 레지스터 활용:** `s0`–`s15` 등을 `VMOV`로 접근하는 임시 저장소로 사용해 스택 접근을 줄인다. 이때 FP32 곱셈·덧셈으로 FP64를 계산하는 것이 아니다.
- **코드 크기 절충:** SHAKE·NTT를 여러 라운드에 걸쳐 과도하게 펼치지 않는다. 최신 다른 함수의 loop-unroll 지시문까지 모두 금지했다는 뜻은 아니다.
- **타이밍 안전성:** 비밀값에 따른 분기·메모리 주소 선택을 피하고, 마스크·carry·고정된 계산 경로를 활용한다. 알고리즘 전체가 항상 같은 사이클이라는 뜻은 아니며, 전력 분석·fault 공격 방어까지 제공하는 것도 아니다.
- **인트린직 여부:** 논문 M4의 주요 최적화 수단은 **별도 어셈블리 + 인라인 어셈블리 + C 수준의 메모리·알고리즘 개선**이다. 같은 저장소에 있는 AVX2/SSE2/NEON 인트린직은 다른 아키텍처용 경로이므로 M4 논문의 기법과 구분해야 한다.

## 6. 현재 ref와 논문을 혼동하면 안 되는 부분

확인한 현재 커밋은 `a5f15894bf1a68017074650d5298cecf9bb29a79`다.
비교용 2025년 스냅샷은 `745ee05b17167335c346e5e7edcc15b4a367d112`(2025-01-26)이다.
**논문은 정확한 커밋을 고정해 쓰지 않았으므로, 이 스냅샷을 논문의 검증된 공식 artifact 커밋이라고 단정하지 않는다.**

| 이후 변경 | 논문 설명과 구분할 점 |
|---|---|
| 2025-05, FP 연산 어셈블리 개선 | 명령 수가 여러 차례 줄었고 `fpr_of32`, 전용 `fpr_sqr`도 추가됐다. 논문 Table 2의 수치와 그대로 일치할 이유가 없다. |
| 2025-06-03, `223cd18` | 서명 계산·임시 메모리 사용 방식이 개선됐다. |
| 2025-06-04, `8ccaee0` | ffSampling 버퍼 배치·복사·스택 사용을 바꾸고 **재귀 진행용 `fndsa_ffsamp_fft_inner` 어셈블리**를 추가했다. 따라서 현재 코드까지 보고 “ffSampling 진행은 전부 C”라고 하면 부정확하다. 가장 깊은 계산 등 C 부분도 남아 있다. |
| 2026-07-22, `bab31dd` | 공개키를 NTT 표현으로 저장하고 `mu` 계산·인코딩·Gaussian 난수 정밀도·키 생성 구현 등을 바꿨다. 현재 검증은 공개키의 NTT 변환을 다시 하지 않는다. 논문 당시 `orig`/`BUFF`와 동일한 연산량·KAT가 아니다. |

즉, **논문 기법은 많이 남아 있지만 현재 코드는 논문 당시 코드와 동일하지 않다.** 최신 코드에서 `-O3`로 측정한 값을 논문 `-O2` 수치와 비교해 모든 차이를 컴파일 옵션 효과로 설명하면 안 된다.
