# Attachment guide and reproduction notes

This bundle is prepared for ST support. It has not been submitted automatically.
No user application/cryptographic implementation is included.

## Captured evidence

`captures/placement`, `captures/wait_controls` and
`captures/write_read_factorial` contain the 25, 20 and 24 completed cases.
Each has its own exact `root.elf`, assembly sources and disassembly. Use the ELF
from the **same series** as the GDB script: controller addresses differ between
series. `results.json` classifies each case; logs and binary dumps are preserved
with documented privacy-only redactions. Original incomplete harness-development
runs are not included or counted. The archive manifest records source and exported
hashes plus each transformation.

The recorded kernel bytes and 128-byte inputs were independently audited against
the ELF and deterministic input formula. Passes require the exact copy/sum and no
fault flags. The original fault status and stacked PCs are in `case-N.log`.

## Tools and configuration provenance

- Arm GNU Toolchain 15.2.Rel1, `arm-none-eabi-gcc` and `arm-none-eabi-gdb`.
- OpenOCD commit `4e9b167e1ae5ccb437eb0538440988b3f0ec53cb` with
  `interface/stlink.cfg` and `target/stm32n6x.cfg` available.
- The setup/server scripts reproduce the command sequences generated by
  [mlkem-native Nucleo host helpers at the pinned commit](https://github.com/pq-code-package/mlkem-native/tree/637d076aa113d8faaec2277ed4a46b657acaf35f/test/zephyr/nucleo_n657x0_q/nucleo_host).
  Generated configuration scripts preserve upstream copyright/license notices.
- The test does not run Zephyr or link its libraries. Its kernels are assembly;
  an application compiler optimization level is not a factor in these tests.

The supplied ELF can be used directly. To rebuild a particular series without
overwriting the captured ELF, from that series directory:

```sh
arm-none-eabi-gcc -mcpu=cortex-m55 -mthumb -nostdlib -x assembler-with-cpp \
  -Wl,-Ttext=0x34080000 -Wl,-e,probe_init \
  tcm_probe.s tcm_root_kernels.s -o rebuilt-root.elf
```

The source `tcm_probe.s` originated in an earlier diagnostic: its header describes
that original probe. For the wait-state controls, the captured GDB script supplies
additional register changes; inspect both script and assembly.

## Hardware safety and preconditions

Use only an idle NUCLEO-N657X0-Q in the debug/RAM-loading boot configuration used
for this capture. This test **clears the entire configured ITCM and DTCM**, writes
reserved AXISRAM and resets the board. It must not run alongside an application.
No Flash or option-byte programming is required. Select the intended ST-LINK
serial explicitly; replace `YOUR_M55_SERIAL` below with the recipient's serial.

These controls assume the boot HSI state (`CFGR1=0`, `HSICFGR=0x8c800000`), ECC ON,
caches OFF and a 256/256 KiB split. In the recorded controls a non-HSI state aborts
before modifying wait-state bits. Do not use the wait-disable cases at 800 MHz or
another configuration on the assumption that this attachment establishes safety.
Do not change locked configuration bits to force the setup to succeed.

## Replay one captured case

The following is a portable rendering of the captured sequence, not a claim of a
newly hardware-validated replay. Work from the extracted bundle root in a path
without spaces. Do not modify `captures` to store new results.

1. Configure the TCM split, using the supplied setup script, then let OpenOCD exit:

   ```sh
   openocd -f openocd-base.cfg -c 'adapter serial YOUR_M55_SERIAL' -f flexmem-setup.cfg
   ```

2. In a separate terminal start a **new** server for each case:

   ```sh
   openocd -f openocd-base.cfg -c 'adapter serial YOUR_M55_SERIAL' -f runtime.cfg
   ```

3. For example, the factorial LDM-copy baseline is case 0; the otherwise identical
   write-default/read-wait-disabled control is case 1:

   ```sh
   mkdir -p replay-output/write_read_factorial
   arm-none-eabi-gdb --batch \
     -x captures/write_read_factorial/case-0.gdb \
     captures/write_read_factorial/root.elf
   ```

   Expected case 0: stop at `probe_fault`, `CFSR=0x8200`, `AFSR=0x20000`.
   Stop the OpenOCD server with Ctrl-C after GDB exits. Start a new server for
   case 1 and use the same command with `case-1.gdb`.
   Expected case 1: stop at `probe_done`, all three fault registers zero, and
   `replay-output/write_read_factorial/output-1.bin` byte-identical to its input.

4. The script restores the saved TCMCR before its reset/detach paths. If manually
   interrupted, do not resume a high-frequency application with diagnostic
   settings left active; re-establish the normal boot/reset configuration first.
   A GDB return code of zero alone is **not** a pass: inspect CASE/status and
   validate the output. Stale BFAR/TEBR DATA values without their VALID flags do
   not by themselves indicate a new fault.

The two other series can be replayed analogously after creating the corresponding
`replay-output/<series>` directory. Captured GDB warnings about MSP/PSP aliases
immediately after loading are retained for transparency; in the completed runs
the initialization/prepare breakpoints and memory dumps passed before each call.

## Privacy and integrity

Local account paths become `<LOCAL_WORKSPACE>` and the originating probe serial
becomes `<REDACTED_PROBE_SERIAL>` in exported text. In GDB scripts, only dump
destinations change to bundle-relative replay paths. No code, data, fault address
or result is edited. `manifest.json` maps each exported file to its original hash
where applicable. It also describes generated setup scripts and documents.
