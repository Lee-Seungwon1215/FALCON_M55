# M4 어셈블리를 유지한 M55 이식·성능 측정

최종 결과와 빌드·실행 로그는 [../result.md](../result.md)에 기록한다.
소스는 이 폴더 옆의 `../ref`다. 복사되어 있던 `../ref/profiling`은 이번
M55 어셈블리 측정에 사용하지 않았으며, 그 안의 과거 수치를 이번 결과로 보지 않는다.

## 실제 변경 범위

원본 커밋은 `a5f15894bf1a68017074650d5298cecf9bb29a79`다.
`ref/inner.h`에 `FNDSA_ASM_CORTEXM55` 명시적 호환 옵션과 검사를 추가했다.
빌드에서 **기존 `FNDSA_ASM_CORTEXM4=1`을 유지**하므로 5개 M4 `.s` 및
키 생성·샘플러의 인라인 어셈블리 경로가 계속 선택된다.
원본의 나머지 C/헤더/어셈블리는 `git show HEAD:<파일>`과 바이트 단위로 대조했다.
기존 `.cpu cortex-m4` 선언은 M4 명령 집합으로 어셈블하도록 그대로 두었고,
M55 ELF에 링크되는 것과 실제 보드에서의 정상 실행을 확인했다.

M4용 빌드도 기존 조건으로 헤더 구문 검사를 통과한다. M55 호환 옵션 없이
M4 ASM을 강제하는 M55 빌드는 여전히 오류가 나도록 검사한다.
`__ARM_ARCH_7EM__` 같은 컴파일러 내장 매크로를 위조하지 않는다.

이 이식은 하드웨어 FP64 또는 MVE 연산으로 다시 구현한 버전이 아니다.
`-mcpu=cortex-m55+nomve`로 이번 기준 실험의 MVE 명령 생성을 끄되,
M4 DSP·정수 어셈블리 최적화는 유지한다. FP 레지스터를 사용하는 VMOV는
기존 정수 어셈블리의 임시 저장 용도이며 FP64 사칙연산을 뜻하지 않는다.

## 빌드와 실행

`Makefile`의 기본 GCC는 M4 측정과 같은 13.2.Rel1 / 13.2.1이다.
STM32CubeN6 기본 경로는 `/private/tmp/STM32CubeN6`다. 경로가 다르면
`ARM_GCC_ROOT=... STM32CUBE_N6=...`를 make 인수로 지정한다.

이 디렉터리에서:

```sh
make all
/private/tmp/falcon-openocd/bin/openocd -f openocd.cfg -c init
```

다른 터미널에서 최초 실행:

```sh
python3 controller.py launch
python3 controller.py status
```

이미 완료된 `results.json`이 있으면 실측 재실행을 거부한다. 결과 보존 후
별도 실험 디렉터리로 준비해야 하며, 기존 결과 파일을 삭제해서 우회하지 않는다.
진행 중 중복 controller는 OS 파일 잠금으로 막는다.

M55 ST-LINK는 `003C00223335510735383531`, 포트는 GDB 3337/TCL 6667이다.
M4 측정 서버의 3336/6666과 분리되어 있다.
이전 M55 프로파일링에서 확인된 development-mode FSBL/SRAM 로딩을 사용한다.
이미지는 `0x34180400`부터 최대 255 KiB 범위만 로드하며 Flash 기록·삭제는 하지 않는다.
종료 후 보드는 halt 상태이고 측정 RAM은 남는다. 원래 실행 중 RAM 복원은 하지 않는다.

## 측정·정확성

M4와 같은 결정적 시드·메시지로 512/1024 각 키 생성·서명·검증 100회를 수행한다.
정확히 같은 seeded/temp API를 DWT로 감싸며, 시드 준비·체크섬·로그는 제외한다.
워밍업 각 1회와 변조 서명 거부를 먼저 확인하고, 호스트 portable C 결과와
워밍업 체크섬이 같을 때만 본 측정을 시작한다. 완료 후 600개의 사이클과
정상 반환, 최종 체크섬을 검증한다. 별도의 부채널 안전성 감사는 아니다.

CPU 600 MHz/HCLK 200 MHz, I/D cache ON, 코드·데이터 AXI SRAM2 조건이다.
진행 결과만 마지막 4 KiB SRAM 영역을 MPU Normal non-cacheable로 설정해
계측 중 cache-clean이나 CPU halt 없이 읽는다. 실제 레지스터는 결과 문서에 남는다.
M4의 24 MHz·Flash·캐시 OFF 결과와 하드웨어 조건이 다르므로 코어 단독 비교가 아니다.

재현에 필요한 실제 명령, SHA-256, 이식 패치, 회차별 사이클은 결과와
`logs/`, `session.json`, `results.json`, `build/`에 보존한다.

`python3 verify_artifacts.py`는 보드에 연결하지 않는 사후 검사다.
600개 원시 사이클과 통계를 다시 대조하고, 호스트·완료된 M4 결과의
체크섬 일치, 소스·ELF 해시, 어셈블리 선택 검사, 5개 `.s`의 M4/M55
플래그별 unlinked `.text` 바이트 일치를 확인한다. 최종 링크 주소나
두 CPU의 타이밍까지 같다는 뜻은 아니다.

이번 M55 실행의 사이클 합은 공칭 클럭에서 55.835982초이고, GO 직전부터
DONE을 읽을 때까지의 호스트 관측 시간은 60.017505초다. 공칭 클럭을 전제하면
누락된 2^32-cycle wrap 한 번을 더한 시간은 이 관측 상한을 넘는다.
이는 타이머 일관성 검사이며 외부 계측기로 실제 클럭을 보정한 결과는 아니다.
