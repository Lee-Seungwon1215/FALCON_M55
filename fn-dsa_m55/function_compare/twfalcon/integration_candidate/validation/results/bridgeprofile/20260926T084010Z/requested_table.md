# 회전상수 사전 변환 적용 후 — 요청 형식 재측정

2026-09-26 KST. 현재 `integration_candidate`를 새로 빌드하여 연결된
NUCLEO-N657X0-Q에서 재실행했다. 기존 로그를 재사용한 결과가 아니다.
암호 구현 소스는 변경하지 않았다.

- 조건: M55 800 MHz, ITCM 코드·DTCM 데이터/스택 각 256 KiB, 캐시 OFF,
  GCC 15.2.1 `-O3`, 이전과 동일한 FP 환경·입력 생성·구간 분류.
- 항목별 5배치 × 100회, 각 배치 warmup 10회.
- 분모: **계측된 FFT/iFFT 함수 전체 시간**. 전체 키 생성이나 계산 코어만의 시간이 아님.
- 계산 구간은 전체 core 시간에서 상수 준비를 빼므로 이중 합산하지 않는다.

| 측정 구간 | FFT 512 | iFFT 512 | FFT 1024 | iFFT 1024 |
| --- | ---: | ---: | ---: | ---: |
| 입력: double → 2×FP32 | 11.41% | 10.71% | 10.54% | 9.88% |
| 회전상수 준비 — 사전 변환표 사용 | **1.56%** | **2.30%** | **1.45%** | **2.13%** |
| FFT/iFFT 계산·내부 제어 | 77.21% | 77.78% | 78.96% | 79.52% |
| 출력: 2×FP32 → double | 9.74% | 9.14% | 9.00% | 8.44% |
| 외부 제어·계측 잔여 | 0.08% | 0.08% | 0.04% | 0.03% |
| **입력·출력 변환 합계** | **21.14%** | **19.85%** | **19.55%** | **18.31%** |

앞의 다섯 구간 합계가 원시 수치로 100%이고, 마지막 줄은 입력+출력의
소계이므로 다시 합산하지 않는다. 표시 값에는 반올림 오차가 있다.
회전상수의 런타임 Q32 변환은 제거되었으며 남은 준비는 포인터/broadcast
등이다. 어셈블리 내부에서 상수를 읽는 비용은 계산 구간에 포함된다.

## 절대 cycle/call

| 구간 | FFT 512 | iFFT 512 | FFT 1024 | iFFT 1024 |
| --- | ---: | ---: | ---: | ---: |
| 입력 | 13,210 | 13,210 | 26,394 | 26,394 |
| 상수 준비 | 1,811 | 2,835 | 3,635 | 5,699 |
| 계산·내부 제어 | 89,416 | 95,959 | 197,655 | 212,473 |
| 출력 | 11,275 | 11,275 | 22,539 | 22,539 |
| 외부 제어·계측 잔여 | 95 | 93 | 95 | 93 |
| **계측 함수 전체** | **115,807** | **123,372** | **250,318** | **267,198** |

입출력 변환 합계는 512에서 24,485 cycles, 1024에서 48,933 cycles로
[사전 변환 적용 전](../20260926T081746Z/bridge_profile.md)과 같다.
비중이 13~14%에서 18~21%로 오른 것은 변환 자체가 느려져서가 아니라
상수 준비 비용 감소로 **분모인 전체 실행 시간이 줄었기 때문**이다.
계산 구간의 비중 증가도 절대 시간이 같은 비율로 늘었다는 뜻이 아니다.

이번 무계측 공개 함수는 114,725 / 122,446 / 248,357 / 265,412 cycles였고,
계측 복사본은 이보다 0.67~0.94% 느렸다. 표는 임의로 타이머 비용을 빼지
않은 계측 수치이며, 무계측 성능 비교와 구분해야 한다.

출력 동등성 **8,800/8,800건 일치**, 구간 합계 검사 20/20 PASS,
CFSR/HFSR/AFSR=0, TCM/ECC 검사 PASS. 이번은 계측 재실행이며 전체 KAT를
다시 실행한 것은 아니다. 전체 KAT는 같은 구현의 직전 11단계 결과를 참조한다.
