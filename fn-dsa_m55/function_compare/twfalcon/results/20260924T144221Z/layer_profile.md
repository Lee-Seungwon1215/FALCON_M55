# 2×FP32 FFT/iFFT 레이어별 병목 측정

측정일: 2026-09-24. 로그: [raw.log](raw.log), 기계 판독용 결과: [layer_summary.json](layer_summary.json).

## 결론

**FFT 마지막 두 레이어 / iFFT 처음 두 레이어가 변환 코어의 64.95~69.11%를 차지한다.**
이 두 레이어의 유효 butterfly 수는 전체의 25%(512), 22.22%(1024)에 불과하다.
현재 큰 레이어에 적용된 9단계 span 개선이 이 구간에는 적용되지 않는다.
따라서 다음 우선순위는 같은 그룹 내부가 아닌 **여러 그룹을 묶어 네 lane을 채우는 작은 레이어 전용 경로**다.
이번에는 계측과 원인 확인만 했으며, 최적화 후보를 추가하거나 통합 코드를 바꾸지 않았다.

## 조건과 측정 경계

- NUCLEO-N657X0-Q, Cortex-M55, CPU/SYSCLK/HCLK=800/400/200 MHz.
- 코드 ITCM, 데이터·스택 DTCM, 각각 256 KiB; I/D cache off. TCM control=0x99, MSCR=0x1300a.
- GCC 15.2.1, `-O3`, `-mfpu=fpv5-d16`, C contraction/fast-math off.
- FP round-to-nearest, FZ/DN on. DWT CYCCNT, 계측 중 IRQ mask.
- 각 크기·방향별 warmup 10회 + 독립 결정적 입력 100개. 원본/계측 없는 복사본/계측 복사본을 6가지 실행 순서로 교대.
- 각 경로의 입력·출력 버퍼 주소 동일. 입력 변환, 비교, 초기화, 출력은 타이머 밖.
- FFT 입력은 정수부 [-1024,1024] + Q32 소수부. iFFT 입력은 동일 입력을 현재 FFT로 변환한 값이며 이 준비 FFT는 타이머 밖.
- 레이어별로 타이머 한 쌍만 사용. 레이어 내부 twiddle 준비·패딩·복사·함수 호출을 포함.
- 분모는 **계측된 FFT 또는 iFFT 한 번의 전체 코어 시간**이다. 키 생성 전체나 NTRU solve 비중이 아니다.
- 독립 레이어, iFFT scaling, 나머지를 합치면 정확히 100%. 표에서는 반올림 오차가 있을 수 있다.
- 빈 타이머 쌍은 9 cycles. 이를 기계적으로 빼지 않았다. `나머지`는 레이어 사이 제어·집계·함수 진입/종료 비용이며, 모든 계측 영향을 뜻하지 않는다.

## 왜 느린가 / 다음 후보

코드: `tw32_mve/fft_tw32_mve.c`의 `ds32_fft_mve()` / `ds32_ifft_mve()`와
`tw32_mve/tw32_primitives_cm55.s`의 `ds32_bfly_fwd4()` / `ds32_bfly_inv4()`.

1. ht=2는 네 lane 중 두 개, ht=1은 한 개만 유효하다. 나머지 lane에도 동일한 FP 연산 명령을 실행한다.
2. C가 각 그룹의 계수를 임시 배열에 옮긴 후 기존 비-span 어셈블리를 호출하고 다시 저장한다.
3. 비-span 어셈블리의 큰 임시 스택 프레임이 남아 있다. 이전 84→36/44 벡터 메모리 명령 개선은 `*_span` 반복에만 적용했다.
4. 작은 레이어는 그룹 수가 많아서 같은 유효 butterfly 수를 더 많은 함수 호출로 처리한다.

확인한 것은 **이 구간 전체의 병목**이다. 이 네 원인의 기여도를 각각 따로 측정해 분리한 것은 아니다.
다음 후보는 ht=2에서 두 그룹, ht=1에서 네 그룹을 한 벡터로 묶고 lane별로 서로 다른 twiddle을 배치하는 방식이다.
우선 레이어 병합/정밀도 감소 없이 데이터 배치와 호출 단위만 바꾸어 출력 동등성을 유지하는 것이 검증하기 쉽다.
처리한 lane 수 증가가 그대로 전체 4배 향상이 되는 것은 아니다. gather/scatter·twiddle 재배열·FP 보정 비용까지 재측정해야 한다.

## 검증과 한계

- 원본/비계측 복사본/계측 복사본: warmup 포함 880건 **전체 구조체 raw byte 일치**, mismatch=0.
- 측정용 복사본에서 PROFILE 타이머 줄만 제거하면 원본 함수 본문과 정확히 일치. helper도 비교 통과.
- 기존 span 회귀: 1,408건 일치. 기존 7단계와 전체 변환 비교: 180건 일치.
- Q32 대비 최대 FFT 차이 135 LSB, round-trip 3,607 LSB: 종전 2×FP32와 동일. **Q32 중간값과 bit-identical인 것은 아니다.**
- canary 손상 0, CFSR/HFSR/AFSR=0, 계측 합계 오류 0, 프로그램 exit=0.
- 기존 네 입력 클래스 timing probe를 함께 재실행했고 클래스 내/간 변동은 0~1 cycle 범위. 전체 상수시간 증명은 아니다.
- 통합 후보 및 정상 코드에는 변경 없음. 전체 키 생성 KAT/서명 회귀는 이번 계측 작업에서 재실행하지 않았다.
  직전 검증 기록은 300/300 keygen KAT, 90/90 서명·검증·변조 거부다.
- 계측 펌웨어 코드 94,980 B, RAM 예약 256,416 B / 262,144 B. 별도 상수표가 포함된 진단 펌웨어이며 배포 메모리 수치가 아니다.
