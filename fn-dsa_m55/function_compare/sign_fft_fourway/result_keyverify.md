# M55_ref 기준 네 가지 구현: 전체 키생성·검증 재측정

측정일: 2026-09-29. [앞선 전체 서명 비교](result.md)의 **네 암호 소스 트리를 그대로 사용**하여 키생성과 검증도 실제 M55 보드에서 측정했다. 과거 기록의 숫자를 가져와 비교한 것이 아니다.

## 비교 범위 — FFT는 서명용이다

| 이름 | NTT | 서명 FFT 5개 | 키생성 FFT |
| --- | --- | --- | --- |
| 원본 `ref` | 원본 | 원본 | 원본 |
| `ntt_only` | 공통 q-NTT + K4C RNS, pre-SLOTHY | 원본 | 원본 |
| `fft_only` | 원본 | 최적화 | 원본 |
| `ntt_fft` | 공통 q-NTT + K4C RNS, pre-SLOTHY | 최적화 | 원본 |

**여기서 FFT는 `fpoly_FFT()`, `fpoly_iFFT()`, `fpoly_LDL_fft()`, `fpoly_split_fft()`, `fpoly_merge_fft()`의 서명용 최적화다. 키생성 FFT A17은 포함하지 않았다.** 따라서 이 결과를 키생성 FFT 최적화의 효과로 해석하면 안 된다.

## 1. 전체 키생성

각 후보·크기별 100개의 결정적 seed를 두 번 실행한 **200개 측정값의 산술평균**이다. 200개의 서로 다른 seed가 아니다. 평균 cycles는 작을수록 빠르며, 배율은 동일 크기의 원본 평균 ÷ 해당 평균이다.

| 구현 | 512 평균 cycles | 원본 대비 배율 | 1024 평균 cycles | 원본 대비 배율 |
| --- | ---: | ---: | ---: | ---: |
| 원본 M55_ref | 69,223,697.405 | 1.0000배 | 288,474,060.340 | 1.0000배 |
| NTT만 | 63,222,988.460 | **1.0949배** | 269,138,305.445 | **1.0718배** |
| 서명 FFT만 | 69,223,576.675 | 1.0000배 | 288,474,169.510 | 1.0000배 |
| NTT + 서명 FFT | 63,222,989.025 | **1.0949배** | 269,138,393.290 | **1.0718배** |

NTT 단독의 원본 대비 사이클 감소는 **8.6686% / 6.7028%**다. 서명 FFT만 적용했을 때의 차이는 512 약 121 cycle, 1024 약 109 cycle이며 절대 변화율이 모두 **0.0002% 미만**이다. 이를 키생성 최적화 성과 또는 의미 있는 성능 저하로 해석하지 않는다.

키생성의 후보 생성·검사·실패 후 재시도·NTRU solve·키 인코딩을 모두 포함한다. 생성된 키의 해시, 서명·검증, 로그 출력은 타이머 밖이다.

키생성은 seed마다 재시도 횟수가 달라 시간 분포가 넓다. 예를 들어 원본의 512 최솟값/최댓값은 52,998,219 / 143,240,185 cycles이고, 1024는 181,128,813 / 742,973,857 cycles다. 모든 후보에서 같은 seed 100개를 사용했으며 원본과 생성된 키가 일치한다. 서로 다른 seed 집합을 쓴 과거 키생성 평균과 직접 대조하지 않는다.

## 2. 전체 검증

유효한 서명 100개를 각각 두 번 검증한 200개 측정값의 산술평균이다. 서명 생성 시간은 포함하지 않는다.

| 구현 | 512 평균 cycles | 원본 대비 배율 | 1024 평균 cycles | 원본 대비 배율 |
| --- | ---: | ---: | ---: | ---: |
| 원본 M55_ref | 367,121.955 | 1.0000배 | 723,647.545 | 1.0000배 |
| NTT만 | 317,794.970 | **1.1552배** | 619,567.550 | **1.1680배** |
| 서명 FFT만 | 367,121.940 | 1.0000배 | 723,647.605 | 1.0000배 |
| NTT + 서명 FFT | 317,794.905 | **1.1552배** | 619,567.580 | **1.1680배** |

NTT 단독의 원본 대비 사이클 감소는 **13.4361% / 14.3827%**다. 서명 FFT 유무로 생긴 평균 차이는 0.1 cycle 미만이다.

검증 API 내부의 디코딩·Hash-to-Point·q-NTT·다항식 계산·노름 검사를 포함한다. 유효한 서명 검증이 성능 지표이며, 변조 서명의 거부는 타이머 밖에서 확인했다. 이 표는 변조 입력의 거부 속도나 개별 NTT 커널 속도 표가 아니다.

## 3. 결과 해석

- **키생성:** 공통 q-NTT와 NTRU solve의 RNS NTT 최적화가 효과를 낸다. 키생성 FFT는 `kgen_fxp.c` 등의 별도 고정소수점 경로로, 이번 서명용 `fpoly_*` 다섯 함수를 호출하지 않는다.
- **검증:** `vrfy.c`에서 공통 q-NTT/iNTT를 사용한다. 이번 서명용 FFT 함수는 검증 경로에 없다.
- 따라서 **원본 ≈ 서명 FFT만**, **NTT만 ≈ NTT+서명 FFT**라는 결과가 호출 구조와 일치한다.
- 서명 FFT 코드는 생성 키의 정상 동작을 확인하거나 검증 입력 서명을 준비할 때 실행되지만, 두 성능 타이머 밖이다. 그 과정의 변경이 실행 전 상태나 인터럽트 위상에 영향을 줄 수 있으므로 미세한 측정 차이를 새로운 알고리즘 이득으로 해석하지 않는다. 미세 차이의 원인을 한 가지로 확정한 것은 아니다.

앞선 서명 표까지 함께 보면, **NTT는 키생성·서명·검증 모두를 개선했고, 이번 서명 FFT 다섯 함수는 서명을 추가로 개선했다.** 세 연산의 배율을 평균 내거나 같은 함수의 커널 배율로 취급하지 않는다.

## 4. 조건과 공정성

| 항목 | 이번 네 구현에 공통 적용 |
| --- | --- |
| 보드 | NUCLEO-N657X0-Q, ST-Link `003C00223335510735383531` |
| CPU | 800 MHz |
| 빌드 | GCC 15.2.1, 동일 Zephyr/보드 설정, `-O3`, Cortex-M55, hard-float, `-mfpu=fpv5-d16`, `-ffp-contract=off`, `-fno-fast-math` |
| 원본 ASM | M4 정수 어셈블리 ON, M55 호환 ON, 모든 후보 공통 |
| 메모리 | 코드 ITCM, 상수·데이터·스택 DTCM, I/D cache OFF, TCM `0x99` |
| 배치 | 변경 영역의 동일 크기 슬롯, 무관한 함수·데이터가 이동하지 않도록 통제 |
| 반복 | 연산·크기별 워밍업 3회 + timed 100회, 후보별 두 번 실행 |
| 키생성 타이머 | `k_cycle_get_64()`, IRQ/SysTick ON; 긴 후보 재시도에도 32비트 넘침을 피함 |
| 검증 타이머 | DWT CYCCNT, IRQ OFF; 앞선 서명 측정의 타이머 정책과 같음 |
| 키생성 입력 | 앞선 서명 실험의 `seed_for(..., phase=1)` 규칙, index 0–99 |
| 검증 입력 | 앞선 서명 실험과 같은 index 9의 키, 동일 메시지·서명 seed 100개 |
| 비교 기준 | 각 연산 내에서 동일 입력·동일 타이머·동일 배치 정책 |

**키생성의 IRQ ON은 앞선 서명 측정의 IRQ OFF와 다르다.** 네 후보의 키생성끼리는 같은 조건이며, IRQ 처리 비용도 모두 포함한다. 각 실행 시작의 100 ms 타이머 교차검사에서 64비트 타이머와 DWT의 차이는 모두 −408 cycles로 확인됐다. 이는 약 8천만 cycle 구간의 약 0.00051%다.

실제 ELF에서 변경하지 않은 함수 **253개**, 데이터·상수 심볼 **136개**의 주소·크기가 네 후보 모두 일치했다. SK/PK/서명/tmp/샘플/스택 주소도 일치한다. 기존 서명 전용 펌웨어와 새 키생성·검증 전용 펌웨어 사이의 모든 주소까지 동일하다는 뜻은 아니다.

새 측정용 C 파일과 실행·집계 도구만 추가/확장했다. 네 후보의 암호 소스 및 원본 작업 폴더는 그대로다. 기존 서명 ELF와 결과는 보존했다. 배치 증거는 [layout_audit_keyverify.json](layout_audit_keyverify.json), 소스 증거는 [source_manifest.json](source_manifest.json)에 있다.

실행 순서: `ref → ntt_only → fft_only → ntt_fft → ntt_fft → fft_only → ntt_only → ref`.

두 실행 간 평균 차이는 키생성 최대 1.39 cycles, 검증 최대 0.13 cycle이었다. 이는 이번 고정 입력의 반복성 확인이지 다른 키·메시지·하드웨어 환경까지의 성능 보장은 아니다.

## 5. 검증 범위

- 새 timed 실행: 키생성 **1,600회**, 검증 **1,600회**, 총 **3,200회** 정상 완료.
- timed 키생성마다 타이머 밖에서 서명·정상 검증·변조 거부 PASS.
- timed 검증마다 유효한 서명 수락 및 타이머 밖의 변조 거부 PASS.
- 크기별 생성된 SK/PK 100개의 누적 SHA3-256이 모든 후보·두 반복에서 일치.
- 크기별 검증 입력인 PK·서명 100개의 누적 SHA3-256도 모든 후보·두 반복에서 일치. 다른 서명을 넣어 측정한 비교가 아니다.
- 모든 실행에서 로드된 section 대조, 완료 marker, CFSR/HFSR/AFSR = 0, TCM/ECC 상태 검사 PASS.
- 각 실행 전후 및 최종 원본·후보 암호 소스 해시 검사 PASS.

동일 소스의 upstream 서명 KAT 360/360, 키생성 KAT 600/600 통과 기록은 [앞선 결과](result.md)에 있다. **이번 추가 작업에서 그 KAT 전체를 새 펌웨어로 다시 실행했다고 주장하지 않는다.** 이번에는 새 timed 입력의 원본 대비 출력 일치와 정상 서명·검증·변조 거부를 검사했다. 모든 입력의 동등성이나 전체 상수시간성을 새로 증명한 것도 아니다.
