# Guard 수정 후 M55 커널 재측정 및 근사 k 연산비중

2026-09-23. 실제 `q32_trial` 본체의 guard 수정 후 재측정했다.
**알려진 KAT 불일치 수정과 별개로, 이 FP64+Q32 호환 보정 후보의 성능 문제는
그대로 확인됐다.** 이것은 보정 없는 일반 FP64 FFT 전체에 대한 판정이 아니다.
암호 소스는 이전 [guard/KAT 합격 상태](guard_integration_result.md)에서 변경하지 않았다.
여기서 원본은 이 프로젝트 `reference/`의 고정소수점 FFT 경로이며, 이미 적용한
NTT 최적화까지 제거한 최초 FN-DSA 전체 구현을 뜻하지 않는다.

## 1. 조건 및 두 측정의 구분

- NUCLEO-N657X0-Q, serial `003C00223335510735383531`.
- CPU 800 MHz, cache OFF, ITCM 코드 / DTCM 데이터·상수·스택, 각 256 KiB.
- GCC 15.2.1, `-O3 -mfpu=fpv5-d16 -ffp-contract=off -fno-fast-math`.
- 기존 M4 정수 ASM 및 M55 MVE NTT 활성화. DWT 사이클, IRQ 비활성화.
- 커널: 이전과 같은 실제 frozen NTRU 입력 19개, 10회 준비 + 100회 측정.
  고정소수점과 FP64를 **한 ELF, 같은 데이터 배열 주소**에서 번갈아 실행했다.
  동일 ELF를 보드에 다시 로드한 2차 측정에서 KPERF 266개 기록이 모두 같았다.
- 비중: 원본 `reference`와 본체 `q32_trial`로 **실제 키생성**을 실행했다.
  512/1024 각각 upstream `test0`..`test99`, 차수마다 준비 실행 1회는 제외.
  `solve_NTRU_intermediate()`의 도달한 모든 후보·재귀 크기·반복을 합산했다.
  NTRU 소스의 빌드용 사본에 타이머만 삽입했고 원래 암호 소스는 수정하지 않았다.
  계측문을 제거하면 원문과 byte-for-byte 같은지 생성 단계에서 확인했다.

두 비교군의 비중 측정은 **서로 다른 ELF**이며 함수·데이터 주소를 강제로
일치시키지 않았다. 커널 속도와 비중 계측값은 서로 다른 종류의 지표다.
비중 계측의 절대 시간은 타이머와 코드 배치 영향을 포함하는 진단값으로 본다.

## 2. 커널 속도 재측정

비율은 **FP64 시간 / 고정소수점 시간**. 1보다 크면 느리다.
일반 상태와 큰 k 상태 두 개에 동일 가중치를 줬고, 추가 진단 case 18은
이 차수별 평균에서는 제외했다. 19개 전체 원시 결과는 아래 summary에 있다.

| 커널 | FFT 크기 | 고정소수점 cycles | FP64 cycles | FP64/고정소수점 |
|---|---:|---:|---:|---:|
| FFT | 256 | 55,925 | 940,385 | **16.82배 시간** |
| FFT | 512 | 126,039 | 2,141,800 | **16.99배 시간** |
| iFFT | 256 | 63,752 | 1,412,189 | **22.15배 시간** |
| iFFT | 512 | 143,334 | 3,220,731 | **22.47배 시간** |
| 점별 복소 곱셈 | 256 | 8,756 | 201,954 | 23.06배 시간 |
| 점별 복소 곱셈 | 512 | 17,460 | 403,810 | 23.13배 시간 |
| 제곱합·역수 준비 | 256 | 454,574 | 270,796 | **0.596배: 40.43% 단축** |
| 제곱합·역수 준비 | 512 | 909,102 | 541,588 | **0.596배: 40.43% 단축** |
| FFT→점곱→iFFT→정수 k | 256 | 130,653 | 2,567,835 | 19.65배 시간 |
| FFT→점곱→iFFT→정수 k | 512 | 291,293 | 5,792,984 | 19.89배 시간 |
| 역수 준비 과정+반복 1회 | 256 | 641,130 | 3,778,994 | 5.89배 시간 |
| 역수 준비 과정+반복 1회 | 512 | 1,326,412 | 8,476,350 | 6.39배 시간 |

위 FFT 크기는 키 크기가 아니다. 대상 intermediate 구간에서 키 512의 최대
FFT 크기는 256, 키 1024는 512다. 커널의 반복 구간은 기존 측정 프로그램과
동일하게 FFT→점곱→iFFT→정수 변환만 포함하며 새 guard 호출은 포함하지 않는다.
새 guard 비용은 아래 실제 키생성 비중에서 따로 포함했다.

이번 커널 결과는 이전 측정과 같다. guard는 FFT butterfly 산술을 바꾸지 않았고,
기존 floor/wrap 등 호환 보정은 그대로다. 실제 `vadd.f64`, `vmul.f64`를 확인했고
`__aeabi_d*` 소프트웨어 double helper는 없었다.

## 3. 실제 키생성에서 근사 k 연산비중

**분모 = 아래 서로 겹치지 않는 계측 구간 시간의 합 100%.** 전체 키생성이나
NTRU solve 전체의 비중이 아니다. 정수 해 갱신, NTT/RNS/CRT, 다른 solve 단계,
계측 구간 밖의 scale/반복 제어 및 타이머 집계 처리는 이 분모에서 제외했다.

| 연산 | 키 512 고정소수점 | 키 512 FP64 | 키 1024 고정소수점 | 키 1024 FP64 |
|---|---:|---:|---:|---:|
| 정수 입력 → FFT 입력 변환 | 24.62% | 2.90% | 28.94% | 3.22% |
| FFT: 준비 f + 반복 F | 24.69% | **35.05%** | 24.59% | **35.06%** |
| 제곱합·역수 준비 | 15.79% | 0.85% | 11.80% | 0.63% |
| 점별 복소 곱셈 | 6.42% | 11.72% | 6.13% | 11.00% |
| iFFT | 26.39% | **48.59%** | 26.55% | **49.24%** |
| 정수 k 반올림 + 안전 검사 | 2.09% | 0.90% | 1.99% | 0.85% |
| 합계 | 100% | 100% | 100% | 100% |

표시값 반올림 때문에 열 합에 0.01%p 차이가 생길 수 있다. 원시 시간으로는
정확히 100%이며 같은 시간을 둘 이상의 항목에 포함하지 않았다.
원본에는 FP64용 guard가 없으므로 마지막 항목은 원본의 정수 반올림과 비교한다.

### 같은 100개 키에서 누적한 구간 시간

| 키 크기 | 고정소수점, cycles/key | FP64, cycles/key | FP64/고정소수점 |
|---|---:|---:|---:|
| 512 | 5,902,117 | 65,325,029 | **11.07배 시간** |
| 1024 | 15,856,436 | 177,006,677 | **11.16배 시간** |

이는 위 분모의 누적 시간을 100으로 나눈 값이지, 전체 키생성 cycles/key가 아니다.
단독 커널 표의 「역수 준비+반복 1회」와 달리, 이 표는 모든 재귀 크기에서
준비와 반복의 실제 실행 횟수를 반영한다. 따라서 두 표의 지연 비율이 다르다.
계측한 각 단계의 호출 횟수는 원본·후보에서 동일했다(후보 전용 guard 제외).

프로파일에는 타이머 비용을 임의로 빼지 않았다. 빈 구간 1,000회 측정 평균은
원본 10, 후보 13 cycles. 이 비용×계측 횟수의 단순 추정치는 구간 합의
원본 0.79%, 후보 0.11% 수준이다. 레지스터 압박·코드 배치 영향까지 보정한
정확한 overhead 값이라는 뜻은 아니다.

### 해석

- 후보 시간의 **83.64% / 84.30%**가 FFT+iFFT다. 현재 지배적인 부분이다.
- 마지막 정수 반올림·안전 검사 합은 **0.90% / 0.85%**다. 이 항목만 줄여서는
  현재의 큰 격차를 해결할 수 없다.
- 입력 변환의 비중이 낮아졌다고 입력 변환 자체가 빨라진 것은 아니다.
  실제 누적 시간은 원본보다 약 1.30배 / 1.24배이며, FFT가 훨씬 느려져
  상대적인 비중이 작아진 것이다.
- 역수 준비 자체는 여전히 약 40.4% 빠르지만 전체 근사 계산의 이득으로
  이어지지 못했다. **이 결론을 전체 키생성의 11배 지연으로 바꾸어 말하면 안 된다.**

## 4. 정확성 및 상수시간 확인

- 비중 계측 펌웨어에서도 원본·후보 각각 **200/200 키 KAT·NTRU 식·범위 PASS**.
- 원본/후보의 실제 digest 200개가 서로 같고, 계측 전 M55 KAT 결과와도 같았다.
- 커널의 실제 입력 19개에서 최종 k와 원본 fixture 모두 일치. 두 번 모두 통과.
- 이전에 확인한 primitive 곱셈 경계값 반례는 여전히 재현된다. 모든 입력의
  동등성이 증명됐다는 의미는 아니다.
- 상수시간 문제도 남아 있다. 같은 n=256 FFT에서 fixed는 zero/unit/tiny 모두
  55,864 cycles, 후보는 각각 909,924 / 940,388 / 918,652 cycles였다.
  반복 측정의 커널 통계 266개는 모두 일치했고, primitive 타이밍의 일부 기록만
  50회 중 1회에 1 cycle 차이가 있었다. 입력 의존 차이와 구분된다.
- 모든 보드 실행에서 환경 검사 통과, CFSR/HFSR/AFSR=0.
