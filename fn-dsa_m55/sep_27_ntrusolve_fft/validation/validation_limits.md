# Validation contract and limitations

Current source cleanup and fresh validation are tracked in
[cleanup/README.md](cleanup/README.md); earlier A17 runs below retain their
original source versions and are not automatically inherited.

2026-09-28 clarified scope: speed, numerical error, KAT, sign/verify and
constant-time testing only. These five checks are complete for the recorded
test sets; see the [scoped summary](security/README.md). Numerical differences
and finite timing coverage remain explicit limitations, not universal proofs.
The deployment work listed below is outside this request, not a blocking gate.

Current A17 update: [security assessment](security/README.md) records expanded
candidate/numerical, API/guard and M55 timing tests. Production crypto is unchanged.
ASan runtime initialization is blocked even for a minimal control program;
all-input FP-domain/error, full memory/stack and physical leakage proofs remain
absent. The benchmark build does not connect sysrng to an embedded entropy source.
Do not interpret historical A16 notes below as complete A17 security approval.

- Original keygen KAT: 300 cases (100 each at n=256/512/1024). Expected values
  copied unchanged from upstream. Every tested key also satisfies the exact
  integer polynomial NTRU equation, not merely a modular check.
- Independent-seed KAT: 300 additional cases generated by the frozen baseline.
  This is supplementary equivalence evidence, not an official upstream KAT.
- Signature KAT: 90 upstream cases over logn=2..10, key + signature digest,
  signature verification and rejection after a one-bit signature alteration.
- Numerical kernel experiment: same bounded Q32 input arrays, logn=1..10,
  32 patterns per direction. Records raw-word errors AND rounded discrepancies.
  DS/FP64 need not match every intermediate fixed word. Passing rounded tests
  and KAT does NOT prove all-input equivalence or an error bound for every NTRU
  iteration.
- Arithmetic tests: B's decoder 261120 finite-exponent samples, 1M raw-boundary
  comparisons and 1M products on the M55; A's exact-representable Q32 decoder
  1M cases under host UBSan. Host tests do not validate emitted ARM instructions.
- Whole key generation includes candidate rejection and retries and therefore
  is not constant-duration across seeds. CT evidence concerns fixed-public-size
  arithmetic, operand-derived addresses/branches and operation timing.
- Inspected A2 point multiply: conversions are hardware VRINTM/VCVT, products
  use inline integer UMULL/UMLAL-family arithmetic, only the public-count LE loop.
  B raw decoder uses fixed shifts/masks and predicated selections, no secret
  branch. Predication alone is not proof of leakage absence.
- B's 14 operand classes have identical measured timing for raw decode and
  multiply in the corrected harness. IRQs are masked during these tests.
  The first raw benchmark hoisted a pure function call; its raw timing is
  rejected. Corrected log: arithmetic/20260927T143511Z.
- The first FFT kernel harness did not enable DWT. Zero cycle measurements
  are INVALID, even though numerical tests completed. Its `review.json`
  explicitly rejects timing. The corrected harness enables/checks DWT and
  warms the two paths before measuring.
- Full formal CT proof, power/EM leakage assessment, exhaustive input bounds
  and worst-case stack proof are NOT claimed. Board fault/ECC checks and linker
  fit are necessary but not sufficient for all these properties.
- A4/A5's inherited FP64 divider had operand-dependent timing. See ct_results.md:
  A6 removes both branch and predicated-selection rewrites and passes the
  dedicated 16-class timing/result test. Do not treat old A4 KAT success as CT.
- Linked A6 sign-test firmware reserves 65536 bytes for the main stack and
  uses 250920/262144 bytes of DTCM overall (including that reservation and
  test buffers), leaving 11224 bytes unallocated. No worst-case stack
  watermark/exhaustive proof was performed. This is link fit, not a stack proof.
- B6 sign-test firmware also uses 250920/262144 DTCM bytes; code is 118580
  bytes in ITCM. The new rounder adds a bounded private 64-byte scratch plus
  callee-saved vector registers. Passing tests/link fit is not a worst-case
  stack proof.
- B5/B6 boundary tests compare against frozen B4 scalar code: encoder 1M raw
  words and 2070 full conversions; rounder 1,273,664 values, output words AND
  range-valid results. They are separate from FFT approximation-error tests.
  See boundary_results.md and ct_results.md; finite test success must not be
  promoted to universal key-equivalence or side-channel guarantees.

All reported results must be tied to the archived ELF and source hashes.
No passing result is inherited after a production source change without re-test.

B8's sign-test link uses 120644 bytes of code and 250920/262144 DTCM bytes
(including the 64-KiB reserved stack and test buffers). Four-coefficient
tiles reserve at most 128 bytes plus callees' scratch/save areas; link fit
and successful runs still do not prove a worst-case stack bound.
The new decoder has been compared on 2,228,448 finite inputs whose components
remain finite after scaling by 2^32. It is not a general NaN/Inf decoder API.
Point/inverse/division tests cover 1600 finite cases, including aliasing and
untouched output memory. Original whole-FFT equivalence for every possible
NTRU input is still not proved by this local translation check.
