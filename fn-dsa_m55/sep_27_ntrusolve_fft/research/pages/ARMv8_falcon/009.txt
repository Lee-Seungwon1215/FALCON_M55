vector register into 64-bit unit. Since the parallel unit has been
changed from 16-bit to 32-bit due to multiplication opera-
tion, the subsequent operation processing must be divided
into two parts and performed separately. Step 24-25 is the
process of converting an 8 ×16-bit input vector register into
two 4 ×32-bit vector registers to perform mq-add, which
processes operations in 32-bit units. Steps 27-39 perform the
parallel processing of mq-add in a 128-bit vector register by
32-bit units. When the mq-add operation is completed, since
the CT-Butterfly of one part is finished, it is necessary to
change the parallel unit from 4 ×32-bit to 8 ×16-bit again,
which is Step 40. Finally, CT-Butterfly operation is final-
ized through mq-sub. Similar to mq-add, since operations
are performed in 32-bit units, the process of integrating the
parallelization of the resulting two vector registers is required.
CT-Butterfly operation is a key operation in NTT, and the
proposed parallel implementation has faster performance by
processing multiple operations simultaneously compared to a
serial implementation.
C. MEMORY OPTIMIZATION STRATEGY: FFT/NTT
Falcon guarantees security based on NTRU lattice, so the
polynomial degree increases with each security level.
In order words, Falcon-512 operates on polynomials of the
512 degree, and Falcon-1024 operates on polynomials of
the 1024 degree If the degree of polynomial is different
according to the security level, the depth of the FFT/NTT is
different. Since memory access is expensive in the embedded
environment, a memory optimization strategy considering the
depth of such FFT/NTT is required. Thus, we present a mem-
ory optimization path for FFT/NTT-512, FFT/NTT-1024.
We designed the memory optimization paths by maximizing
the merging proposed in previous study [27]. For example,
based on FFT-512, it is possible to save 16 LD1 and ST1
memory access instructions each in Real and Image Part for
2 depths compared to Standard implementation. In addition,
by maximizing NEON vector registers v0−v31, coefficients
of polynomial are held and processed in all vector registers
