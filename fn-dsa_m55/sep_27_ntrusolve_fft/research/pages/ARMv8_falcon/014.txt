VI. CONCLUSION
In this paper, We proposed a optimal software of NTT/FFT,
which is the core operation of Falcon Round 3. From an
NTT point of view, it took full advantage of the NEON
vector register to process eight coefficients simultaneously,
accelerating performance over a reference implementation.
From the FFT point of view, we proposed a parallel imple-
mentation that processes two coefficients using the Floating
Point Instruction Set and NEON vector register supported by
the target device. In addition, the Falcon algorithm isn’t based
on a module structure but NTRU lattice, so the degree of the
operation-based polynomial for each security level is differ-
ent. It is based on the 512 degree polynomial operation (res.
1024 degree polynomial operation) by Security Level 1 (res.
Security Level 5). Therefore, a memory-optimized path con-
sidering FFT/NTT depth for each security level is required.
We propose memory optimization paths for each FFT/NTT
for each security level, minimizing the memory access over-
heads that occurs during transform. Through these contri-
butions, we achieved a performance improvement of 210%
by Falcon-512 in NTT and 250% by Falcon-512 in FFT
multiplication compared to the FFT/NTT implementation of
Falcon Round 3 Submission. As a result, integrating the
proposed FFT/NTT optimal implementation technique into
Falcon, we achieved 15.1%, 16.5%, and 65.4% performance
improvement in KeyGen, Sign, and Verify, respectively,
compared to Falcon Round 3 Submission based on Falcon-
512. The proposed FFT implementation methodology and the
optimization method using the merging and register-holding
technique of NTT can be applied to all ARMv8-based devices
including ARM-Cortex A series. Our study is meaningful in
the results of optimizing FFT/NTT-based multiplication, the
core operation of Falcon, for the first time in the ARMv8-A
environment. In the future, we plan to optimally implement
various PQC algorithms such as lattice-based, code-based,
and multi-variable-based in the ARMv8-A environment.
