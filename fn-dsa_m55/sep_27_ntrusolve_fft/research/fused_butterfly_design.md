# A10: exact Q32 butterfly fusion, without SLOTHY

## Motivation and scope

A9 had five forward span calls (sum, three products, combine) and six inverse
calls (also prepare/half), plus a 3×128×8 = 3072-byte temporary tile. Its
bounded public-twiddle multiplication was faster, but the surrounding call,
save/restore and temporary-array work remained inside the transform.

A10 writes the whole four-coefficient butterfly directly in one local
assembly loop. It does not change the NTRU algorithm, Babai iteration policy,
Q32 representation or rounding, candidate norm, NTT/CRT/Bezout, or signing.
The depth0 double/DS path is unchanged. This optimizes the fixed portion of
A's hybrid; it is NOT described as a native FP64 FFT rewrite.

## Exact arithmetic retained

Let `mul(x,t)` be the original signed Q32 product, truncated after multiplying,
then wrapped to 64 bits. The three products remain:

    z0 = mul(y.re, s.re)
    z1 = mul(y.im, s.im)
    z2 = mul(wrap(y.re + y.im), wrap(s.re + s.im))
    product.re = wrap(z0 - z1)
    product.im = wrap(z2 - wrap(z0 + z1))

Each product retains its own truncation. No four-product substitution, FMA
rounding change or discarded low bits are used. Inverse computes the original
`half(add(x,y))` and `half(sub(x,y))` BEFORE multiplying the difference by
the conjugated root. `half` retains wrap64(x+1), then signed right shift.
The output convention and per-layer scaling are unchanged.

The A9 limb identity for multiplication is retained (see
[twiddle_multiply_design.md](twiddle_multiply_design.md)). The `t.high=-2`
case now subtracts twice x without using q6/q7:

    (2*x).low  = (x.low << 1) mod 2^32
    (2*x).high = 2*x.high + (x.low >> 31) mod 2^32

Subtract this pair with the original unsigned low-word borrow. This is an
exact identity for ALL raw x, not only small FFT coefficients. It allows the
already computed real product in q6/q7 to remain live through the third multiply.

## Register and memory lifetimes

| Point | q6/q7 | private scratch [0,32) | private scratch [32,64) |
| --- | --- | --- | --- |
| After preparing y | free | wrapped y.re+y.im | free |
| After z0 | free | same | z0 |
| After z1 | z0−z1 | same | z0+z1 |
| After z2 | z0−z1, preserved | no longer needed | used for imaginary combination |
| Butterfly finish | real result | unused | unused |

The imaginary result is placed in q4/q5, leaving q0–q3 for loading x and
forming both output sums/differences. Inputs/outputs keep original interleaved
64-bit words; VLD2/VST2 handle that layout. Private scratch uses SoA vector
loads/stores, not a whole-transform conversion.

The loop uses 64 scratch bytes. The assembly's total frame is 176 bytes:
36 GPR save + 64 extended-register save + 76 local/padding bytes. In the
linked keygen image, the C forward/inverse frames are 208/240 bytes; local
FFT→butterfly chains are therefore 384/416 bytes, versus A9's 3416/3440.
This is local static accounting, NOT a proof of the full keygen worst-case stack.
The common 64-KiB reserved stack is not silently reduced for benchmarks.

## Public specialization, not secret dispatch

Every used original root component has real high word -1/0. The imaginary
high word is 0 forward and -1 after conjugation. The summed constant's high
word is in {-2,-1,0,1}. Classifying those high words and public low-word top
bits yields nine actual tuples per direction, for all 511 used roots.

Eighteen loop bodies and a 128-entry (512-byte) address table are directly
written in the candidate's own assembly. Dispatch occurs once per span and
depends only on public constants/direction. Secret coefficients only affect
lane-local carry/borrow predicates, not branches, loop lengths or addresses.
Unsupported public-root classes trap; this private helper is NOT a generic
complex multiplier. All roots generated by logn≤10 loops are covered and
individually tested. The authoring generator is not a production build step.

## Thresholds and independent evaluation

The test varies vector span cutoffs 4/8/16. Four is fastest in both directions
for useful sizes. Complete transforms still lose at the smallest sizes, so
production retains original forward logn<5 and inverse logn<4. These public
thresholds are literal C conditions, not build/backend selectors. Calls in
solve_NTRU_intermediate remain the same three NTRU-local calls as in A9.

The test-only implementation is first compared with both A9 and original
kernels in one ELF. The chosen algorithm is then directly written into the
candidate source, followed by fresh current-source gates. No trial file or
other candidate crypto is linked into final keygen. B14 is not modified.

## Source of ideas and limits

Revisited local `m55_ntt-ftt_opt.pdf` pp.18–19 for eight-register management,
overlap opportunities, and amortizing repeated-operand preparation;
`TWfalcon.pdf` p.18 for avoiding ABI-induced spills and using public operand
structure. Those are design inspirations, not proofs of Q32 rounding rules
or promises of this implementation's performance. The fixed limb/half and
register-lifetime arguments above come from the actual original code.
No SLOTHY schedule, Montgomery formula or FP32 precision relaxation is used.

Finite raw-bit/KAT/timing checks and manual assembly review do not establish
universal key equivalence, a formal constant-time proof or power/EM resistance.
The target 1.7× whole-keygen acceleration is NOT implied by kernel gains.
