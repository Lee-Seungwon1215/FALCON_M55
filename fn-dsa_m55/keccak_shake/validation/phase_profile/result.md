# 최종 Keccak process_block 내부 시간 비중

측정일: 2026-09-29. 대상: `../../sha3_cm55.s`의 현재 최종 C9 구현.
**분모는 `fndsa_sha3_process_block()` 한 번의 전체 시간**이다.
FN-DSA 전체 키생성/서명/검증이나 SHAKE API 전체의 비중이 아니다.
배포용 암호 소스는 변경하지 않고 생성한 계측 복사본만 실행했다.

## 결과

계측하지 않은 원본 호출은 **약 12,521 cycles = 15.651 µs**였다.
아래는 M55 DWT 실측에서 계측 비용을 뺀 구간별 추정치다.
모든 구간에는 해당 구간의 load/store와 주소 계산도 포함된다.

| 구간 | cycles/호출 | 시간, 800 MHz | 전체 비중 |
| --- | ---: | ---: | ---: |
| 입력·출력, 비트 분리/복원 | 2,021 | 2.526 µs | 16.14% |
| θ 보정 + ρ/π 회전·재배치, 24라운드 | 5,976 | 7.470 µs | **47.73%** |
| χ + 다음 라운드 열 XOR 누적, 24라운드 | 4,320 | 5.400 µs | **34.50%** |
| 초기 준비·ι·루프 제어·복귀/계측 잔여 | 약 204 | 0.255 µs | 1.63% |
| 합계 | 약 12,521 | 15.651 µs | 100.00% |

가장 큰 단일 구간은 θ·ρ·π다. χ만 최적화해도 전체 시간의 약 34.5%에
영향을 주는 것이므로 χ의 커널 개선율이 전체에 그대로 반영되지 않는다.
단, 이 측정만으로 θ·ρ·π를 MVE로 바꾸면 빨라진다거나 메모리가 원인이라고
단정할 수는 없다. 회전 산술/메모리/파이프라인 stall을 개별 분리한 표는 아니다.

마지막 21 cycles는 전체 원본 시간에서 계측 구간들의 보정 합을 뺀 값이다.
함수 복귀 등 타이머 바깥 작업과 계측으로 인한 잔여 차이가 섞여 있으므로
순수 epilogue의 직접 측정값이라고 해석하면 안 된다.
상단 표의 기타 약 204 = 58 + 119 + 6 + 잔여 약 21이다.

같은 펌웨어에서 별도 호출한 split 묶음(`_5`×4 + `_1`)과 merge 묶음은
각각 **924 cycles**, 합계 1,848 cycles였다. 전체 대비 약 14.76%지만
이는 입출력 행에 포함되는 작업의 별도 측정이므로 위 표에 더하지 않는다.

## 조건·재현성·계측의 한계

- 보드: NUCLEO-N657X0-Q, serial `003C00223335510735383531`.
- CPU 800 MHz, 코드 ITCM / 데이터·스택 DTCM, 각각 256 KiB, I/D cache OFF.
- GCC 15.2.1, `-O3`, 기존 mlkem-native 기반 보드 설정/로더 유지.
- 원본과 계측본 함수 시작 주소 모두 `0x10000844`; 상태 `0x30002220`, 타이머 배열 `0x30002020`.
- DWT_CYCCNT, 측정 중 IRQ OFF, 5배치 예열 후 100표본, 배치당 64회 호출.
- 외부 타이머는 빈 루프 차감. 내부 표본은 각 배치 마지막 호출의 24라운드 전부를 기록.
- 원본/계측본은 같은 입력 생성·검사·측정 프로그램. 타이머 8개 정적 위치가 호출당 77번 실행된다.
- 연속 타이머 보정 함수의 fixed/indexed 네 조합이 모두 6 cycles였다.
- trace 두 실행, 각 100표본에서 모든 내부 구간 값이 같았다.

계측으로 실제 증가한 시간은 461 cycles, 인접 타이머로 추정한 비용은
462 cycles이다. 보정 후 원본 전체와 **−1 cycle, 약 −0.008%** 차이였다.
타이머 삽입은 명령 배치/파이프라인에도 영향을 주므로, 총합 차이가 작다는
사실이 각 구간의 오차도 1 cycle 이하임을 증명하지는 않는다.
비중은 원본 전체를 분모로 한 계측 보정 추정치이며, 오차를 감추기 위해
각 구간을 일괄 재비례하지 않았다.

## 정확성·보존 확인

모든 유효 실행에서 helper 5,120건, 전체 Keccak 상태 oracle 1,024건,
SHAKE256 hashlib 7벡터, callee-saved ABI 16건, guard/fault 검사를 통과했다.
CFSR/HFSR/AFSR=0, TCM 제어 0x99, ECC 검사 상태 정상이다.
타이머는 구간 경계에서 죽은 R2/R3만 사용하며 APSR·Q 레지스터·SP를 변경하지 않는다.
helper/inject 1,284 bytes는 byte-identical, plain `.text` 전체도 배포본과 동일하다.
trace의 `.text`는 192 bytes(8개 × 24 bytes) 증가했다.

이번에는 암호 구현을 변경하지 않았으므로 전체 FN-DSA KAT/서명 재측정은 하지 않았다.
이는 구간 계측의 정확성 점검이지 모든 입력에 대한 형식 증명이나 신규 보안 인증이 아니다.
