# M55 Keccak process_block 최적화 결과

## 2026-09-30 — 원본/A14 네 항목 독립 계측

원본 `sha3_cm4.s`와 현재 A14 `sha3_cm55.s`에 같은 **작업 분류**를 적용하고,
한 번에 한 항목만 계측하는 펌웨어 8개와 무계측 기준 2개를 실제 M55에서 실행했다.
암호 소스는 변경하지 않았다. 측정 코드는 `validation/four_part_profile/`에 있다.

**아래 네 행은 계측 비용을 보정한 독립 계측값이다. 무계측 실행 시간의 정확한
네 조각이라고 해석하면 안 된다.** 특히 원본의 π/열 XOR, A14의 χ/열 XOR은
명령이 섞여 있다. 구간을 나누는 타이머가 명령 겹침과 대기 시간을 바꾸므로,
정확한 native 구간별 배율까지 확정한 것은 아니다.

| 독립 계측 항목 | 원본 cycles | A14 cycles | 원본/A14 | A14 사이클 변화 |
| --- | ---: | ---: | ---: | ---: |
| 상태 입출력 — 비트 변환 제외 | 277 | 175 | 1.583× | 36.82% 감소 |
| 비트 분리·복원 | 1,848 | 232 | 7.966× | 87.45% 감소 |
| 24라운드 계산 — 열 XOR 누적 제외 | 9,537 | 11,496 | 0.830× | 20.54% 증가 |
| 열 XOR 누적 — 첫 라운드 준비 포함 | 1,276 | 1,425 | 0.895× | 11.68% 증가 |
| **별도 무계측 `process_block()` 전체** | **13,383** | **12,504** | **1.07030×** | **6.568% 감소** |

### 계측 경계와 해석

- 상태 입출력: 외부 25-lane 상태 ↔ 내부 표현의 load/store·주소 처리 및 경계에서
  필요한 사전/지연 회전. 비트 split/merge 호출과 ABI 저장·복구는 제외한다.
- 비트 변환: 원본은 실제 호출되는 split/merge 10회, A14는 내부 `K_MERGE4`와
  `K_SPLIT4` 2회를 측정했다. 같은 외부 상태 형식을 유지하기 위한 전체 변환 비용이다.
  원본은 각 방향 21 lanes, A14는 각 방향 4 lanes만 변환하므로, **동일 lane 수의
  비트 연산 자체가 7.966배 빨라졌다는 뜻이 아니다.** 이전 helper 924 cycles씩은
  원본의 동일 5-call sequence이며, A14가 실제로 쓰는 새 변환의 비용과 구분한다.
- 라운드: θ 보정·ρ/π·χ·ι, 관련 데이터 이동을 측정하되 열 parity 전용 연산은
  일시 중단/재개 경계로 제외했다. 루프 복귀 분기 등은 계측 밖 잔여에 일부 남는다.
- 열 XOR: 초기 열 합산과 이후 parity 준비를 직접 계측했다. 원본의 공유 load/store는
  π에, XOR+ROR 융합 명령과 누적용 회전은 parity에 귀속시켰다. A14의 q6/q7 초기화,
  XOR 누적, C 배열 store를 포함한다. 원본은 초기+23회, A14는 초기+24회이며
  A14가 마지막에 계산하지만 사용하지 않는 parity도 실제 실행 비용으로 포함한다.

**교란 점검:** 네 독립 값을 합하면 원본 12,938 cycles, A14 13,328 cycles다.
무계측 전체에 비해 각각 −445 cycles(−3.325%), +824 cycles(+6.590%)다.
ABI/제어 잔여와 계측에 따른 실행 배치·파이프라인 변화가 섞인 차이이며, 이 차이를
개별 항목의 오차 상한이나 신뢰구간으로 간주할 수 없다. 네 값을 더해 전체 개선을
계산하거나 100% 비중으로 정규화하지 않는다. 특히 0.830×·0.895×는 **참고 계측 배율**이지
원래 함수에서 각각 정확히 그만큼 느려졌다는 확정값이 아니다.

**분리하지 않은 대조 실험도 추가했다.** 초기 parity부터 마지막 라운드 종료까지
타이머 한 쌍만 넣은 `core` 실행은 원본 **11,228**, A14 **12,057 cycles**였다.
라운드+열 XOR 묶음은 **0.93124×**, 즉 **7.383% 느림**이다.
이 묶음에 위 입출력·변환 값을 더하면 원본 13,353, A14 12,464 cycles로,
무계측 전체와의 차이는 각각 30(0.224%), 40(0.320%) cycles로 줄었다.
이는 세부 분리 계측이 특히 라운드/XOR의 상대 비용을 왜곡한다는 교차 확인이며,
분리된 두 배율을 확정값으로 채택하지 않는 이유다. 묶음 측정도 개별 stall의
기여도를 형식적으로 증명하는 것은 아니다.

실용적인 전체 흐름은 다음과 같다: 입출력+변환에서 약 **1,718 cycles 절약**,
라운드+열 XOR 묶음에서 약 **829 cycles 추가**, 나머지 차이 10 cycles를 합쳐
전체는 **879 cycles 감소**했다. 즉, 전체 이득의 주원인은 경계의 표현 변환 감소다.

### 공통 조건·검사·재현

- 같은 NUCLEO-N657X0-Q (`003C00223335510735383531`), CPU 800 MHz, 캐시 OFF.
- 코드 ITCM, 상수·데이터 DTCM, 각각 256 KiB 설정. GCC 15.2.1, 같은 `-O3` 측정 환경.
- 상태 객체 `0x30003000`(실제 25-lane 배열은 +32), 측정 스택 상단 `0x30005000`을
  양 구현에서 고정하고 ELF 심볼을 검사했다. 타이머 보정도 같은 낮은 DTCM 스택을 사용한다.
- 동일 결정적 입력, warm-up 5회, 표본 100개, 배치 64회. 구간 값은 각 배치의 마지막
  호출 전체 24라운드에서 누적한 값의 중앙값이다. 전체 커널은 64회 평균의 중앙값이다.
- 동일한 8-instruction timestamp probe. 빈 구간 64개를 표본마다 보정했고 **8 cycles**로
  일정했다. APSR/GE/VPR/Q/LR를 바꾸지 않으며 R0와 측정용 R9를 보존한다.
- 각 채택 펌웨어에서 Keccak 독립 oracle 1,024회, SHAKE256 7 KAT 벡터,
  split/merge 5,120건, ABI 16건, guards 통과. CFSR/HFSR/AFSR=0.
- FN-DSA 전체 키생성·서명 KAT는 이번 구간 계측 작업에서는 재실행하지 않았다.
  암호 소스가 그대로인 상태에서 Keccak/SHAKE 출력 동등성을 재검사한 것이다.
- 영 상태·난수 상태 각 1,000회 시간도 로그에 저장했다. 상수시간 형식 증명은 아니다.
- 최초 계측기의 큰 버퍼가 일반 스택 위치를 옮겨 무계측 시간부터 달라졌으므로 해당
  초기 실행은 비교에서 제외했다. 스택을 옮긴 첫 시도에서 PSPLIM stack fault 1건도
  발생했으며, 측정 스택용 제한 저장·복원 후 재실행한 통과 기록만 사용했다.
  중간의 높은 스택에서 구한 9-cycle 보정 결과 역시 최종 수치로 사용하지 않는다.

## 현재 코드 — 전체 MVE 유지, 지연 원인 수정 완료

14개 수정 후보를 실제 M55에서 비교하고 **A14**를 `sha3_cm55.s`에 직접 반영했다.
모든 상태 산술은 MVE 정수 ASM이다. 주소·공개 카운터·ABI만 스칼라다.
SLOTHY, FP 산술, 후보를 연결하는 빌드 옵션/링크는 사용하지 않았다.

| 구현 | process_block cycles | 원본 대비 속도 |
| --- | ---: | ---: |
| 원본 M4 ASM, 같은 M55 재측정 | 13,382 | 1.00000× |
| 이전 C9 혼합형 | 12,521 | 1.06876× |
| 최초 전체 MVE A0 | 17,689 | 0.75652× |
| **최종 전체 MVE A14** | **12,504** | **1.07022×** |

A0 대비 **29.312% 사이클 감소 / 1.41467배**, 원본 대비 **6.561% 감소**.
이전 혼합형보다 차이는 17 cycles(0.136%)뿐이므로 사실상 비슷한 수준이다.
전체 MVE의 성능 저하는 해결했지만 원본보다 수 배 빨라졌다는 의미는 아니다.
이 표는 process_block 커널이며 FN-DSA 전체 성능이 아니다.

### 원인과 해결

입출력보다 라운드 내부의 반복 gather·회전 준비·중복 처리와 명령 배치가 주요 문제였다.
내부를 low32/high32로 바꾸고, ι를 χ/parity에 결합하고, 다음 입력/주소표를 미리 읽도록
MVE load·ALU·store를 교차 배치했다. 마지막 lane도 scalar fallback 없이 처리한다.
연속 입출력은 VLD2/VST2로 변경했다.

| 구간 | 최초 전체 MVE | 최종 | 최종 비중 |
| --- | ---: | ---: | ---: |
| 입출력·분리/복원 | 1,627 | 425 | 3.399% |
| θ + ρ/π | 9,336 | 7,536 | 60.269% |
| χ + 열 XOR (최종은 ι 포함) | 5,760 | 4,320 | 34.549% |
| 초기화·제어·복귀/계측 잔여 | 966 | 223 | 1.783% |
| 합계 | 17,689 | 12,504 | 100% |

구간별 값은 계측 비용 보정 추정치이며 개별 stall의 기여도를 확정한 값은 아니다.

## 이전 혼합형 C9 기록

**아래는 이전 구현의 보존 기록이며 현재 파일의 성능·비중이 아니다.**

이전 C9의 [내부 구간 시간 비중 실측](validation/phase_profile/result.md):
입출력·분리/복원 **16.14%**, θ·ρ·π **47.73%**, χ·다음 열 XOR **34.50%**,
초기화·제어·복귀/계측 잔여 **1.63%**. 분모는 `process_block()` 전체 약 12,521 cycles이며,
계측 비용을 보정한 추정치다. 이 추가 계측에서 배포 소스는 변경하지 않았다.

### C9 채택 당시 — keccak_ref 기반 후속 실험

2026-09-29 후속 후보 9개를 실측하고 **C9: 두 회전 교차 배치 + χ 입력 재사용**을 채택했다.
실제 본문은 이 폴더의 `sha3_cm55.s`에 직접 반영했다. 다른 암호 소스, helper,
외부 통합 경로, 빌드 선택 옵션은 변경하지 않았다. SLOTHY는 사용하지 않았다.

| 비교 대상 | process_block cycles | 원본 대비 속도 |
| --- | ---: | ---: |
| 원본 M4 ASM을 같은 M55에서 실행 | 13,382 | 1.00000× |
| 직전 MVE | 12,569 | 1.06468× |
| **현재 최종 C9** | **12,521** | **1.06876×** |

원본 대비 **6.434% 사이클 감소**, 직전 MVE 대비 **0.382% 감소**다.
새 배치에서 원본과 최종 모두 평균/중앙값/최소/최대가 표의 값과 같았다.
이는 `process_block()` 전체 호출의 결과이며 FN-DSA 전체 개선율이 아니다.

큰 폭의 추가 개선은 얻지 못했다. 중복 load를 크게 줄이는 재배열 후보,
4라운드 결합 후보, ρ·π의 벡터 gather/회전 후보는 모두 더 느렸다.
전체 후보와 실패/탈락 이유는 [후속 실험 보고서](validation/keccak_ref_experiments.md)에 기록했다.
최종 χ의 입력 읽기량은 라운드당 600→480 B로 줄었지만 단독 속도는 동률이었고,
48-cycle 이득은 두 회전의 교차 배치를 적용한 비교에서 나타났다.
이는 정적 명령·데이터 흐름 및 비교 측정에 기반한 설명이며 stall별 시간 분해는 하지 않았다.

원본/최종 함수 진입 주소: 모두 `0x10000844`.
최종 자체 스택 최대 832 B로 직전과 동일하며 원본보다 648 B 많다.
최종 함수+상수 2,164 B, ASM `.text` 3,448 B:
직전 대비 16 B, 원본 대비 736 B 감소했다.
helper/inject 1,284 B는 원본과 byte-identical이다.

최종 소스 SHA-256:
`94f441fffa66e32adecd6d6c69b46b37583bee62607c764ccd0813aa3772361a`

정리 후 바이너리 `.text`는 C9 탐색본과 동일하다.
추가 외부 구현 의존성이나 후보 선택 분기는 없다.

## 이전 단계 기록 — 12,569-cycle 채택 당시

**아래 기록은 보존용이며 현재 최종 수치는 위 표를 사용한다.**

측정일: 2026-09-29. 대상은 이 폴더의 **`sha3_cm55.s`에 직접 작성한 `fndsa_sha3_process_block()`**이다.
원본 `sha3_cm4.s`, `sha3.c`, 분리·복원·inject 보조 함수와 다른 암호 함수는 변경하지 않았다.

## 최종 커널 성능

분리·복원, 24라운드, 상태 입출력, 함수 진입·복귀를 모두 포함한 호출당 평균이다.
동일한 최종 측정 프로그램으로 원본과 최적화본을 비교했다.

| 대상 | 원본 M4 ASM을 M55에서 실행 | 최종 MVE ASM | 사이클 감소 | 속도 배율 |
| --- | ---: | ---: | ---: | ---: |
| **process_block 전체** | **13,382 cycles** | **12,569 cycles** | **6.0753%** | **1.06468×** |
| 분리 루틴 묶음 (`_5`×4 + `_1`) | 924 | 924 | 변경 없음 | 1.000× |
| 복원 루틴 묶음 (`_5`×4 + `_1`) | 924 | 약 924 | 변경 없음 | 약 1.000× |

분리·복원 묶음은 별도 어댑터로 측정한 값이며, 첫 행에도 이미 해당 작업이 포함된다.
세 행을 더하면 안 된다. 개별 `_1`은 48, `_5`는 219 cycles로 동일했다.
최종 후보 두 실행에서 복원 묶음은 100표본 중 한 배치에서만 1 cycle 차이가 났다
(호출당 평균 924.000156 cycles).

앞서 기록한 원본 13,383 cycles는 이전 검사 프로그램의 값이다.
ABI·입력 클래스 검사를 추가한 최종 프로그램에서는 원본이 13,382 cycles로 측정됐다.
원인을 특정한 것은 아니며, 개선율은 **동일한 최종 프로그램에서 얻은 비교값**으로 계산했다.

이것은 FN-DSA 키생성·서명·검증 전체의 6.08% 개선을 뜻하지 않는다.
이번에는 해당 세 작업의 총 성능을 새로 측정하지 않았다.

## 구현 내용

1. χ의 네 열과 다음 θ의 열 XOR 누적을 MVE `4×32-bit` 정수 논리 연산으로 처리.
2. θ의 D 주입과 ρ·π 회전·재배치를 결합. 중간 A 저장/재읽기 제거.
3. χ 결과를 계산하면서 다음 라운드의 열 XOR도 누적.
4. ι 라운드 상수를 레지스터에 지연 보관해 A[0]/C[0]의 별도 load/store를 줄임.
5. even/odd 평면 배치와 스칼라 다섯 번째 열/MVE 명령 순서를 직접 조정.

일부 회전·재배치와 다섯 번째 열은 스칼라로 남겨 두었다.
**모든 명령을 MVE로 바꾼 것은 아니며, FP 산술이나 SLOTHY도 사용하지 않았다.**
최종 함수 내부에는 다른 후보를 선택하는 런타임 분기가 없다.

## 후보별 진행 기록

모든 유효 후보는 Keccak oracle과 SHAKE256 검사를 통과한 뒤 측정했다.
최종 후보 이전의 수치는 당시 검사 프로그램으로 측정한 탐색 기록이다.

| 후보 | process_block cycles | 판정 |
| --- | ---: | --- |
| θ·χ를 우선 벡터화한 기본 구현 | 15,562 | 원본보다 느려 탈락 |
| θ→ρ·π와 χ→다음 θ를 결합 | 13,648 | 개선됐지만 원본보다 느림 |
| 홀수 평면 +4-byte 배치 조정 | 13,528 | 아직 원본보다 느림 |
| ι 상수 적용의 중복 메모리 접근 제거 | 13,313 | 소폭 개선 |
| **벡터·스칼라 교차 스케줄링** | **12,569** | **현재 채택** |

초기 구현의 첫 실패는 라운드 상수 4개 항목의 전사 오류였다.
1라운드 진단과 상수표 전체 대조로 수정했다. 현재는 원본 24개 상수 쌍을 자동 비교한다.
실패한 실행과 1라운드 진단 기록은 보존했지만 유효한 성능 결과로 사용하지 않았다.
각 후보의 소스도 해당 실행 폴더의 `sources.tar.gz`에 보존되어 있다.

## 측정 조건과 재현성

- NUCLEO-N657X0-Q, ST-Link `003C00223335510735383531`.
- M55 800 MHz, I/D cache OFF.
- 코드 ITCM, 데이터·스택 DTCM, ITCM/DTCM 각각 256 KiB 설정.
- GCC 15.2.1: `-O3 -mcpu=cortex-m55 -mthumb -mfpu=fpv5-d16 -mfloat-abi=hard`.
- `-ffp-contract=off -fno-fast-math -fno-strict-aliasing`.
- DWT CYCCNT, 계측 구간 interrupt OFF, 출력은 계측 밖.
- 대상별 워밍업 5배치 + **100표본 × 표본당 64호출**.
- 타이머/빈 루프 비용을 뺀 값. 함수의 BL/반환 및 분리·복원 비용은 유지.
- 원본·최적화본의 함수 시작 주소 모두 `0x10000844`.
- SHAKE256 `r=17` 커널. FN-DSA-512/1024가 공통으로 사용하는 함수 기준이다.
- 최종 최적화본 두 실행은 동일 ELF와 동일 통계를 재현했다.

최종 원본 평균: 13,382.000156 cycles, 중앙값 13,382, 표준편차 0.001563 cycles/호출.
최종 후보 평균/중앙값/최소/최대: 모두 12,569 cycles/호출.
표준편차는 64호출 배치의 호출당 값에 대해 계산했다.

상수시간 점검:

- 최종 바이너리에서 조건 분기는 공개된 24라운드 카운터의 `bne` 하나이다.
- 비트 분리·복원 호출은 각각 고정된 5회이며 입력에 따라 달라지지 않는다.
- 스택/상태 배열/라운드 상수 주소는 공개 포인터와 고정 오프셋·라운드 번호만 사용한다.
- 데이터 의존 테이블 인덱싱, 나눗셈 명령, 간접 호출은 추가하지 않았다.
- 영(0) 상태와 난수 상태를 각각 1,000회 단독 측정: 두 클래스 모두 **12,572 raw cycles**.
  이 값은 빈 루프 보정 전 단독 호출이므로 위 배치 보정값 12,569와 구분한다.
- 두 클래스에서 관측 분산도 0이었다. 이 경우 Welch t 통계량은 정의되지 않으며,
  관측된 시간 차이가 없었다는 결과만 기록한다.

이는 제한된 입력 시험과 코드/바이너리 검토다.
**모든 입력의 동등성·상수시간의 형식적 증명이나 전력/전자파 부채널 검증 완료를 뜻하지 않는다.**
