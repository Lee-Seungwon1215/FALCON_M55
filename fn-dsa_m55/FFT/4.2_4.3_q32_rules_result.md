# 4.2 / 4.3 Q32 규칙 보정 결과 — 2026-09-27

## 결론

**두 후보에 연속 2×FP32 표현을 유지하면서 주변 산술 Q32 규칙을 구현했고,
M55 원본 키생성 KAT 300/300 + 새 입력 300/300이 각각 일치했다.**
서명 KAT·검증·변조 거부도 각각 90/90 통과했다.

그러나 **모든 입력의 동등성까지 해결한 것은 아니다.**
B의 별도 합성 연결 시험에는 최종 정수 k 차이가 남고, FFT/iFFT 중간 결과도
원본과 다르다. 전체 키생성 성능도 기준보다 느리므로 **통합 ref로 채택하지 않았다.**

## 무엇을 유지하고 바꿨나?

| 항목 | 4.2 B | 4.3 C |
| --- | --- | --- |
| 입출력 경계 | 정수 → Q32 → DS … DS → Q32 → k | 정수 → DS … DS → k |
| 중간 작업 배열 | 계속 2×FP32 | 계속 2×FP32 |
| FFT/iFFT | 기존 로컬 MVE FP32 어셈블리 유지 | 기존 로컬 MVE FP32 어셈블리 유지 |
| 주변 산술 | FP32 + 절삭/wrap/carry 정수 보정 | FP32 + 절삭/wrap/carry 정수 보정 |
| 나눗셈 | 원본 로컬 고정 반복 정수 나눗셈 | 원본 로컬 고정 반복 정수 나눗셈 |

**4.1처럼 중간 Q32 다항식 배열로 되돌리지 않았다.** 다만 순수 FP32만의 구현은 아니다.
원본 재실행, 실패 seed 특례, 다른 후보 코드 링크는 없다.
[산술과 정밀도 한계](4.2_4.3_q32_rules_notes.md)에 상세히 기록했다.

## 정확성

| 검사 | B | C |
| --- | ---: | ---: |
| 원본 키생성 KAT (256/512/1024 각 100) | 300/300 | 300/300 |
| 새 seed, 원본 oracle 비교 | 300/300 | 300/300 |
| 위 600개 정수 NTRU 방정식 | 600/600 | 600/600 |
| 서명 KAT·서명검증·변조 거부 | 90/90 | 90/90 |
| bounded 산술, 호스트 100만 입력쌍 | 변환/덧셈/곱셈 차이 0 | 동일 |
| 폭넓은 산술, 호스트 100만 입력쌍 | 표현된 입력의 DS 투영 곱셈 차이 0 | 동일 |
| 임의 전체 64-bit Q32를 DS로 무손실 표현 | 불가 | 불가 |
| 합성 연결 시험 | 일부 최종 k 차이 남음 | 시험한 입력의 k 차이 0 |
| 일반 입력 동등성/전체 상수시간 증명 | 아님 | 아님 |

폭넓은 산술 검사는 먼저 DS로 표현된 입력을 기준으로 비교한다.
원래 64-bit 입력의 손실이 없다는 검사가 아니다. 이 손실도 호스트 로그에 남겼다.
B/C 합성 시험은 입력 분포가 다르므로 마지막 k 차이 수만으로 후보의 정확성을
서로 순위 매길 수 없다.

## 전체 키생성

동일 원본 seed 100개/크기, warm-up 3회, 실패 재시도 포함.
NUCLEO-N657X0-Q/M55 800 MHz, 코드 ITCM·데이터/상수/스택 DTCM,
캐시 OFF, GCC 15.2.1 -O3, M4 어셈블리 및 MVE NTT ON.
비교는 같은 측정 프로그램·배치 정책이며 함수별 주소를 완전히 고정한 실험은 아니다.

| 구현 | 512 평균 cycles | 1024 평균 cycles |
| --- | ---: | ---: |
| M55_ref | 62,738,244.07 | 261,716,429.65 |
| ntt_opt | 56,951,252.87 | 243,157,429.06 |
| 4.1 | 54,272,283.72 | 230,887,527.13 |
| B | 70,938,388.01 | 271,877,299.73 |
| C | 72,938,525.49 | 276,756,184.03 |

다음 표의 **양수는 개선이 아니라 시간 증가(느려짐)** 이다.

| 보정판 | M55_ref 대비 512 / 1024 | ntt_opt 대비 512 / 1024 | 4.1 대비 512 / 1024 |
| --- | ---: | ---: | ---: |
| B | +13.07% / +3.88% | +24.56% / +11.81% | +30.71% / +17.75% |
| C | +16.26% / +5.75% | +28.07% / +13.82% | +34.39% / +19.87% |

4.1은 이번 최종 소스 시험 뒤 다시 측정했다. M55_ref와 ntt_opt는 같은 날 앞서
동일 조건으로 측정한 기록을 썼다. 모든 성능 실행은 키생성 200/200 일치했다.

## 왜 느려졌나?

FFT/iFFT 어셈블리는 그대로라서 해당 내부 커널의 이득은 유지된다.
하지만 주변 산술에서 FP32 계산 + Q32 변환·정수 보정이 겹치고,
나눗셈도 원본 정수 알고리즘을 사용한다. C의 동일 ELF 커널 측정에서는
512/1024 점별 복소곱이 원본 대비 약 60.8배/60.9배 시간이 걸렸다.
이 비용이 FFT의 이득을 상쇄했다. 이 수치는 전체 키생성이 60배 느리다는 뜻이 아니다.

## 시간 검사

새 보정 함수만 따로 분리해 3크기 × 3연산 × 8입력 종류 × 100회 측정했다.
B/C 모두 클래스별 평균 차이는 최대 0.01 cycle, 개별 min/max 범위는 최대 1 cycle였다.
정적 검사에서 새 helper 두 개의 비밀 조건 분기를 제거했지만 IT 조건 실행은 남는다.
따라서 측정한 범위에서 큰 시간차를 관측하지 않았다는 결과이지, 전체 상수시간 증명은 아니다.

B의 기존 큰 연결 구간 시험은 클래스별 평균에 약 3 cycle 차이가 있었다.
같은 실제 입력인 op0 일부 클래스 사이에도 차이가 나서, 이를 새 산술의 비밀값 의존
시간차로 확정하지 않았다. 단독 시험과 구분해 로그를 보존했다.
