# 4.2 / 4.3: FP32 workspace + Q32 arithmetic compatibility (2026-09-27)

## What changed

Both candidates remain independent local implementations. Their polynomial workspace is
still two FP32 components per real value (four floats per complex value). There is no
new intermediate Q32 polynomial array, original-FFT replay, seed-specific exception, or
fallback to a second solver.

Only the following production files changed in this pass:

- `kgen_ds_q32.h`: new local scalar compatibility primitives.
- `kgen_fft_mve.c`: inverse/norm, complex point product and real denominator division
  call the local compatibility primitives; obsolete native reciprocal helpers removed.

`kgen_ntru.c`, `kgen_ds.h`, `kgen_fxp.c`, and `kgen_fft_cm55.s` retain their
pre-pass bytes. In particular, MVE FFT/iFFT butterflies have **not** been rewritten to
emulate every internal Q32 operation.

## Still different from 4.1

| Implementation | Workspace between FFT, point arithmetic and iFFT |
| --- | --- |
| 4.1 | Q32 arrays; surrounding arithmetic is the original fixed-point implementation |
| 4.2 B | DS arrays; original integer-to-Q32 and final Q32-to-k boundaries retained |
| 4.3 C | DS arrays; direct integer-to-DS and DS-to-k boundaries retained |

B and C contain their own copies of the compatibility helpers and their own MVE source.
They do not include or link cryptographic files from one another.
The normal validation harness selects each folder's own sources; there is no
compile-time arithmetic-selector workaround.

## Rules implemented

1. Q32 grid: floor to a 2^-32 grid, with modulo-2^64 storage semantics.
2. Sum/subtraction: FP32 TwoSum followed by the Q32 grid/wrap boundary.
3. Product: FP32 multiplication/FMA residual, followed by exact low-word correction.
   Products of sufficiently large magnitude require full-width integer carry assistance.
   Both correction computations execute and a mask selects the result: no secret-size
   fallback branch is intended.
4. Complex product: the original three-product formula, including its intermediate
   addition/subtraction wrap boundaries (not an algebraically rearranged four-product rule).
5. Inverse preparation: each real/imaginary square is rounded separately, then summed.
   The scaled real and negated imaginary numerators are divided separately.
6. Division: call the same local `inner_fxr_div()` fixed-count integer quotient primitive.
   This intentionally includes the original raw-zero denominator behaviour rather than
   substituting a floating-point reciprocal or a new input rejection condition.

This is **FP32 storage and FP32 arithmetic with integer assistance**, not a claim that
every operation is native FP32. The original integer multiplication correction and
integer division have an explicit cost. There is no claim that this version is fast
merely because it passes KAT.

## Why not simply floor the native DS product?

A bounded 1,000,000-pair diagnostic initially found 6,838 one-Q32-LSB product differences.
The low-word correction removed those differences. Further large-magnitude tests found
that the signed low-word correction becomes ambiguous; full-width carry assistance
removed the tested projected-product differences.

The correction is deliberately local to scalar operations: the polynomial remains in DS
storage. This is not an optimization of the correction yet.

## Precision limits

- Two floats cannot preserve every arbitrary signed 64-bit Q32 word.
- The bounded test covers inputs in [-64,64) and products within [-4096,4096).
- The wide test first decodes the **represented DS operands**, computes their exact
  integer product with host `__int128`, then projects the answer back to DS. It is not a
  claim of preserving the arbitrary full-width input before conversion.
- Large random raw-Q32 inputs demonstrably lose input bits on DS conversion. Those
  counts are reported, not discarded.
- FFT/iFFT internal intermediate results can still differ from the original fixed-point
  FFT. Passing tested output KATs is not a proof of all-input equivalence.
- The domain is finite scaled NTRU arithmetic, not arbitrary NaN/Inf FP32 inputs.
  Existing final output safety checks remain; the former zero-denominator rejection
  claim is obsolete because original quotient semantics are now preserved.

## Build, memory and timing

The first inline implementation exceeded the validation harness's existing 128 KiB code
guard when sign/verify was linked. The solution was sharing `qd_raw_floor()` and
`qd_mul()` bodies (noinline), not relaxing the linker guard or moving code to slower RAM.
All arithmetic remains in the candidate's own source.

GCC initially compiled a masked shift into an operand-dependent branch. Explicit opaque
mask barriers prevent that rewrite in the tested ELF. `audit_q32_elf.py` checks the two
new helper bodies and reports remaining predicated instructions separately.
A branch scan and finite timing classes are **not** a whole-program constant-time proof.
Key generation has rejection/retry behaviour, which is not reclassified as constant-time.

## Evidence and reproduction

Each candidate's `result.md` links final board logs and manifests. Manifests record
source/ELF/log hashes and build flags. The original KAT expected values are unchanged.
Additional deterministic test inputs use a separate expected table generated by unchanged
`ntt_opt`; the host generator first checks its original 300 upstream vectors.

```sh
bash validation/build.sh kat
bash validation/build.sh extra
bash validation/build.sh sigkat
bash validation/build.sh keygen_current
# B: kernels; C: ds
python3 validation/audit_q32_elf.py extra
```

Use the shared environment Python for `validation/run_board.py MODE`.
Only one process owns the M55 board at a time.

Previous sources, ELFs and reports are preserved under
`validation/history/pre_q32_rules_20260927/`.
