# 서명 LDL·split·merge 최적화 계획

작성일: 2026-09-28

상태: **2026-09-28 사용자 진행 승인 후 구현·보드 검증 완료.**

채택은 LDL **L5b**, split·merge **S6**이다. [실측 결과](schedule_result.md)에
후보 비교·KAT·정확성·서명검증·상수시간 스크리닝과 측정 한계를 기록했다.
SLOTHY 및 `Final_code/Before_slothy` 반영은 하지 않았다.
관찰용 이전 비중은 보존했고 [최종 비중](schedule_profile_result.md)은 별도 작성했다.

아래는 구현 전 합의한 계획 원문이다. 모든 함수 주소를 고정하는 추가 비교까지는
수행하지 않았으며, 특히 LDL의 작은 전체 변화에는 배치 효과가 포함될 수 있음을 결과에 명시했다.

## 1. 목표와 작업 범위

작업은 모두 `fn-dsa_m55/FFT/6_sign_fft` 안에서 수행한다.

1. 현재 native FP64 `fpoly_LDL_fft()`를 직접 어셈블리로 작성하고 수동 스케줄링한다.
2. `fpoly_split_fft()`와 `fpoly_merge_fft()` 내부 계산만 native FP64로 전환한다.
3. 전환으로 빨라진 함수만 직접 어셈블리로 작성하여 추가 스케줄링한다.
4. 후보별 커널 성능과 전체 서명 성능, 정확성·KAT·서명검증·상수시간 점검 결과를 비교한다.

기존 `fpoly_FFT()`·`fpoly_iFFT()` 최적화는 유지한다. 이번 작업에서 SLOTHY는 적용하지 않는다.
`Final_code/Before_slothy`와 `M55_ref`는 수정하지 않는다.

## 2. 현재 기준 코드

| 대상 | 현재 상태 | 다음 작업 |
|---|---|---|
| `fpoly_FFT()`·`fpoly_iFFT()` | `sign_fft_cm55.s`에 채택한 수동 ASM 구현이 있음 | 유지 |
| `fpoly_LDL_fft()` | `sign_fpoly.c`의 C native FP64 산술 + `VLDR/VSTR` 입출력 | 별도 ASM 작성·수동 스케줄링 |
| `fpoly_split_fft()` | C 반복문에서 정수 ASM 기반 FP64 에뮬레이션 사용 | 함수 내부만 native FP64 전환 |
| `fpoly_merge_fft()` | C 반복문에서 정수 ASM 기반 FP64 에뮬레이션 사용 | 함수 내부만 native FP64 전환 |

현재 LDL에도 컴파일러가 생성한 명령 배치는 있다. 아직 적용하지 않은 것은 **사람이 직접 작성한 ASM 스케줄링**이다.
기존 LDL 결과는 [ldl_result.md](ldl_result.md), FFT/iFFT ASM 실험은
[validation/asm_experiments.md](validation/asm_experiments.md)에 보존되어 있다.

서명용 `fpr` 배열은 binary64 비트 패턴을 저장한다. 키생성의 Q32 고정소수점과 구분한다.
기존 저장 형식을 유지하고 FP 레지스터로 직접 읽고 쓴다. 수치 변환용 배열이나 Q32 보정 경로를 추가하지 않는다.

## 3. 1단계: LDL 수동 스케줄링

### 비교 후보

| 후보 | 변경 내용 | 확인할 효과 |
|---|---|---|
| L0 | 현재 C native FP64를 동결 | 추가 개선의 기준 |
| L1 | 현재 계산 순서를 유지한 기본 ASM | 직접 ASM 작성 자체의 효과 |
| L2 | L1에서 독립적인 실수부·허수부 계산을 교차 배치 | 의존 연산 사이 대기 감소 가능성 |
| L3 | L1에서 다음 위치의 입력을 미리 읽도록 배치 | load와 계산 배치 효과 |
| L4 | L1에서 독립적인 두 위치를 한 반복으로 처리 | 루프·주소 계산 감소와 배치 여유 |
| L5 | 서로 결합 가능한 위 기법을 조합 | 단독 후보보다 추가 이득이 있는지 확인 |

L2·L3·L4는 가능한 한 L1 대비 변경 요소를 분리한다. L5는 단독 결과뿐 아니라
기법 간 상호작용을 확인하며, 시험한 조합과 시험하지 못한 조합을 기록한다.
위 표는 초기 실험군이지 가능한 모든 명령 순서를 열거한 것은 아니다.

레지스터 활용은 모든 ASM 후보의 공통 설계 조건이다. 중간값을 레지스터에 유지하고
불필요한 이동·spill을 줄이되, 레지스터 저장·복원 비용도 성능에 포함한다.

### 유지할 계산 규칙

```text
inv   = 1 / g00
mu_re = g01_re * inv
mu_im = g01_im * inv
p_re  = mu_re * g01_re
p_im  = mu_im * g01_im
z     = p_re + p_im
d11   = g11 - z
l10   = mu_re - i*mu_im
```

- 독립적인 명령만 재배치하고, 각 결과의 연산 의존 관계와 반올림 순서를 유지한다.
- 단일 반올림 FMA로의 교체나 수식 재결합은 이번 스케줄링에 포함하지 않는다.
- 입력을 미리 읽더라도 배열 끝을 넘는 접근을 하지 않는다.
- 공개 크기에 따른 작은 크기·잔여 처리 경로를 포함한다.
- 두 위치 묶음은 FP64 SIMD를 뜻하지 않는다. 독립적인 스칼라 FP64 계산을 함께 배치하는 것이다.
- 명령을 교차 배치했다고 실제 실행이 겹치거나 빨라진다고 가정하지 않는다. 보드 측정으로 판단한다.

L0보다 재현성 있는 이득이 없으면 현재 C native FP64를 유지한다.

## 4. 2단계: split·merge native FP64 전환

먼저 채택한 LDL을 고정하여, 이후 측정에 LDL 변경 효과가 섞이지 않게 한다.

| 함수 | 유지할 핵심 흐름 |
|---|---|
| `fpoly_split_fft()` | 합·차 → 켤레 회전상수와 복소수 곱셈 → 각각 ½배 |
| `fpoly_merge_fft()` | 회전상수와 복소수 곱셈 → 합·차 → 기존 배열 위치에 저장 |

- `sign_fpoly.c`에서 두 함수 내부만 수정한다.
- 공통 `FPR_ADD_SUB`, `FPC_MUL`, `fpr_*`는 수정하지 않는다.
- 기존 API, 실수부·허수부 배열 배치, 회전상수 비트 패턴을 유지한다.
- 실수부와 허수부를 각각 하나의 FP64 값으로 계산한다.
- 원본의 복소곱 계산 순서, ½배 처리, 부호 있는 0의 동작을 검사한다.
- 최소 크기의 복사 경로를 유지한다.

먼저 split만 바꾼 경우와 merge만 바꾼 경우를 구분하여 효과를 확인한 뒤,
채택할 함수들을 함께 적용한 상태도 측정한다.

### 진행·중단 조건

- 출력 불일치나 KAT 실패가 있으면 원인을 해결하기 전에는 채택하지 않는다.
- native FP64 전환 후 느려지거나 측정 변동을 넘는 개선이 재현되지 않으면 **해당 함수의 추가 스케줄링을 중단**하고 기존 구현을 유지한다.
- 한 함수가 탈락해도 다른 함수의 독립적인 검증은 계속한다.
- 커널이 빨라도 전체 서명에서 손해가 생기면 바로 채택하지 않고 크기별 호출·배치·호출 비용을 확인한다.

## 5. 3단계: 빨라진 split·merge만 수동 ASM 최적화

각 함수의 native C 버전을 새로운 비교 기준으로 동결한다.

1. 같은 연산 순서의 기본 ASM을 작성한다.
2. 실수부·허수부의 독립적인 곱셈 및 합·차를 교차 배치한다.
3. 다음 계수·회전상수의 선행 읽기를 시험한다.
4. 두 위치 묶음과 중간값의 레지스터 유지를 시험한다.
5. 호환되는 기법을 조합하고, 작은 크기까지 포함한 최선의 구현을 선택한다.

계산 규칙을 바꾸는 최적화와 단순 명령 재배치를 혼동하지 않는다.
ASM이 native C보다 빠르지 않으면 native C를 유지한다.

## 6. 파일 구성과 구현 원칙

| 파일 | 예정 역할 |
|---|---|
| `sign_fpoly.c` | split·merge native FP64 구현 및 최종 함수 정의 정리 |
| `sign_ldl_cm55.s` | LDL 수동 ASM 후보와 최종 채택 구현 |
| `sign_split_merge_cm55.s` | 스케줄링 진행 조건을 통과한 split·merge의 수동 ASM |
| `sign_fft_cm55.s` | 기존 FFT/iFFT 구현 유지 |
| `validation/` | 동결 기준, 커널·회귀검사, 측정 로그, 후보 소스 보존 |

새 ASM 파일명은 위 이름을 사용할 계획이다. 함수 정의를 ASM으로 옮길 때는
중복 심볼을 남기지 않고, 기존 선언·호출 규약을 유지한다.

- 실제 C/ASM 파일을 직접 수정한다.
- 다른 실험 폴더의 소스를 링크하거나 후보 선택용 빌드 옵션·조건부 매크로를 만들지 않는다.
- 새 `.s` 파일을 컴파일하는 일반적인 빌드 목록 등록은 수행한다.
- 측정용 원본·후보 심볼 분리는 검증 프로그램에만 두고 배포 코드에는 넣지 않는다.
- 최종 소스에는 채택 구현을 남기며, 이전·탈락 후보는 소스 스냅샷과 로그로 보존한다.
- `Final_code/Before_slothy`로의 최종 반영은 별도 요청 전에는 하지 않는다.

## 7. 측정과 검증

### 성능

- 커널: `logn=1…10` 전체. 준비·입력 복사는 계측 밖, 함수 호출·입출력·저장/복원 비용은 포함한다.
- 실제 재귀 호출에 작은 크기가 많으므로 512·1024 커널 결과만으로 채택하지 않는다.
- 전체 서명: 512·1024, 동일 키·메시지·seed·반복 횟수로 비교한다.
- 기본 반복 조건은 warm-up 3회, 구현·크기별 100회, 동일 입력으로 2회 실행하여 재현성을 확인한다.
- 커널은 중앙값과 변동 범위, 전체 서명은 평균 사이클과 반복 간 차이를 기록한다.
- 같은 CPU·버스 클럭, ITCM/DTCM·캐시·ECC 정책, 컴파일러·최적화 옵션을 유지한다.
- 내부 프로파일링 계측과 전체 서명 성능 측정은 분리한다.
- 코드·상수·데이터 배치 정책을 맞추고, 작은 개선이 배치 효과인지 의심되면 함수 주소를 맞춘 추가 비교를 한다.
- 코드 크기와 스택/레지스터 저장 비용도 기록한다.

### 정확성·보안 관련 검사

| 항목 | 검사 |
|---|---|
| 출력 정확성·오차 | 동결된 원본과 비트 단위 비교, 무작위·경계·상쇄·부호 있는 0 입력 |
| 메모리 안전성 | 버퍼 guard, 입력 불변 조건, 최소 크기·마지막 반복의 경계 접근 |
| ASM ABI | callee-saved 정수/FP 레지스터 보존, 스택 정렬 |
| KAT | 기존 서명 KAT 일치, 키생성 KAT 회귀검사 |
| 서명검증 | 정상 서명 검증과 변조 서명 거부 |
| 상수시간 정적 점검 | 비밀값 의존 분기·주소·반복 횟수 여부 |
| 상수시간 실행 점검 | 입력군별 실행시간 분포와 차이, 보드 fault 여부 |

원본이 지원하는 입력 영역을 기준으로 시험한다. 유한한 시험의 통과를 모든 입력의
동등성 증명이나 형식적인 상수시간 증명으로 표현하지 않는다. 전력·EM 검사는 이번 범위가 아니다.

## 8. 결과 정리 기준

다음 비교를 구분해서 보고한다.

1. LDL: 현재 native C 대비 ASM 스케줄링의 추가 효과.
2. split·merge: 기존 정수 에뮬레이션 대비 native C 전환 효과.
3. split·merge: native C 대비 ASM 스케줄링의 추가 효과.
4. 전체 서명: 이번 작업 직전 코드 대비 추가 효과.
5. 전체 서명: `M55_ref` 대비 누적 효과. 비교 조건이 같은 기록을 사용하고, 다르면 재측정한다.

속도 배율은 `기준 cycles / 후보 cycles`, 사이클 감소율은
`(기준 cycles - 후보 cycles) / 기준 cycles × 100`으로 표기한다.
실행 소스·ELF·컴파일 명령·로그와 연결해 후보 결과를 남긴다.

## 9. 완료 범위

이번 범위가 끝나면 `fpoly_FFT()`, `fpoly_iFFT()`, `fpoly_LDL_fft()`,
`fpoly_split_fft()`, `fpoly_merge_fft()`의 주요 5개 함수 최적화 실험을 마무리한다.

다만 서명에서 FFT 표현을 사용하는 모든 연산의 최적화가 끝나는 것은 아니다.
`fpoly_split_selfadj_fft()`, 점별 곱셈·덧셈·뺄셈,
`ffsamp_fft_deepest()` 내부의 별도 계산은 이번 변경 대상이 아니다.

최종 통합 상태의 서명 연산 비중을 다시 측정하여 남은 병목을 보고한다.
남은 함수나 SLOTHY로 범위를 자동 확장하지 않는다.
