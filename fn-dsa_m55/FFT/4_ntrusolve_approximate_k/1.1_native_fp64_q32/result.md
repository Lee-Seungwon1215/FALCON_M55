# 1.1_native_fp64_q32 — 새 경로 M55 검증·성능 결과

2026-09-23. **새 경로에서 직접 빌드·M55 재검사·성능 재측정을 완료했다.**
암호 소스 31개는 최신 `function_compare/fft_native_fp64/q32_trial`과 동일하며
이번 작업에서 수정하지 않았다. 다른 후보의 암호 소스를 링크하지 않았다.
NTT 최적화를 유지한 상태의 NTRU ④ 단일-double 연구 기준선이다.

**경로 이식 검증이 완료된 것이지 FP64 최적화나 전체 보안 검증이 끝난 것은 아니다.**
고정소수점보다 느리고 알려진 산술 경계값·입력 의존 실행시간 문제가 남아 있다.

## 1. 검증 결과

| 검사 | 새 경로 결과 |
|---|---|
| M55 원본 키생성 KAT, 256/512/1024 각 100개 | **300/300 일치**, NTRU 방정식·계수 범위 PASS |
| M55 원본 키+서명 KAT, logn=2..10 각 10개 | **90/90 일치** |
| 이전 guard 불일치 seed | **5/5 원본 키 digest 일치** |
| 정상 서명 검증·변조 서명 거부 | **95/95 PASS** (서명 KAT 90 + 회귀시험 5) |
| 별도 연산비중 펌웨어의 키 KAT | **200/200 일치** (512/1024 각 100개) |
| 커널의 frozen 실제 입력 19개 | 최종 정수 k 및 원본 fixture 모두 일치, 2회 실행 모두 PASS |
| 계측 전/후 및 이전 경로의 키 digest | 모두 동일 |
| 런타임 환경 | 모든 실행에서 TCM/ECC 검사 PASS, CFSR/HFSR/AFSR=0 |

5개 회귀시험 seed는 512의 1198·7470, 1024의 1691·4395·10491이며 문자열은
`fp64-audit-20260923-<index>`다. 원본 fixed digest를 기대값으로 사용했다.
KAT 기대값을 변경하거나 이 seed에 대한 예외 처리를 추가하지 않았다.

이전 호스트 20,000개 시험은 여기서 다시 실행하지 않았다. 이 보고서의 새 결과는
위 범위의 실제 M55 검사이며, 모든 입력에서 같은 키를 만드는 형식 증명은 아니다.

## 2. 빌드·배치·측정 조건

- NUCLEO-N657X0-Q / STM32N657, probe `003C00223335510735383531`.
- CPU 800 MHz, cache OFF, ITCM 코드 / DTCM 상수·데이터·스택, 각 256 KiB.
- GCC 15.2.1, `-O3 -mcpu=cortex-m55 -mfpu=fpv5-d16`,
  `-ffp-contract=off -fno-fast-math -fno-strict-aliasing`.
- M4 ASM, M55 ASM 및 MVE MP31 활성화. 성능 계측 중 IRQ OFF, DWT 사용.
- 각 펌웨어에서 로컬 암호 번역 단위 24개를 확인했다. `function_compare`의
  소스가 직접 컴파일되거나 외부 후보로 대체되지 않았음을 검사했다.
- 기존 mlkem-native 기반 Zephyr/부트/링커/보드 로더만 공통으로 사용했다.
- 암호 소스·계측 파일·ELF·컴파일 명령·원시 로그 hash를 기록·대조했다.
- 커널 비교의 fixed/FP64 함수 8개 모두 이전 경로와 실행 주소·크기가 동일했다.
  성능 비교는 같은 ELF 안의 fixed/FP64가 같은 데이터 배열 주소를 사용한다.

| 펌웨어 | ITCM 코드 영역 사용 | DTCM 예약 사용 |
|---|---:|---:|
| 키생성 KAT | 106,468 B | 210,568 B |
| 서명 KAT | 122,384 B | 242,632 B |
| 5-seed 회귀시험 | 121,316 B | 236,552 B |
| 커널 성능·타이밍 | 65,020 B | 210,896 B |
| 실제 키생성 중 연산비중 | 107,092 B | 204,816 B |

모두 링크 영역 한도 안이다. 빌드 출력의 `FLASH`는 이 배치에서 ITCM 코드
영역 이름이며 외부 flash 실행을 뜻하지 않는다. 모든 입력의 최대 스택 사용량을
새로 증명한 것은 아니다.

## 3. 커널 재측정

19개 실제 NTRU 중간 입력, 각 10회 준비 + 100회 측정. fixed/FP64 호출 순서를

비율은 **FP64 시간 / 고정소수점 시간**이고 1보다 크면 느리다.

아래 실제 키생성 비중 계측에는 이들을 포함한다.

## 4. 새 경로의 실제 키생성 중 연산비중

512/1024 각각 동일 `test0`..`test99` 100개 seed. 준비 실행 1회 제외.
`solve_NTRU_intermediate()`의 모든 도달한 후보·재귀 크기·반복을 합산했다.

**분모는 아래 중첩 없는 계측 구간 합 100%**이며, 전체 키생성이나 NTRU solve
전체가 아니다. NTT/CRT/Bezout, 정수 해 갱신, 다른 단계, 구간 밖의 scale/반복
제어와 타이머 집계 처리는 제외한다. 계측 사본은 타이머를 제거하면 원문과 같다.

| 연산 | 키 512 FP64 | 키 1024 FP64 |
|---|---:|---:|
| FFT 입력 변환 | 2.90% | 3.22% |
| FFT: 준비 f + 반복 F | **35.05%** | **35.06%** |
| 제곱합·역수 준비 | 0.85% | 0.63% |
| 점별 복소 곱셈 | 11.72% | 11.00% |
| iFFT | **48.59%** | **49.24%** |
| 정수 반올림·안전 검사 | 0.90% | 0.85% |
| 합계 | 100% | 100% |

표시값 반올림으로 0.01%p의 합계 차이가 생길 수 있다.
후보 시간의 FFT+iFFT 비중은 **83.64% / 84.30%**다.

| 키 크기 | 새 FP64 구간합, cycles/key | 이전 경로 FP64 | 이전 고정소수점 구간합 | 고정소수점 대비 시간 |
|---|---:|---:|---:|---:|
| 512 | 65,325,028.96 | 65,325,028.97 | 5,902,117.13 | **11.07배** |
| 1024 | 177,006,676.91 | 177,006,676.88 | 15,856,435.65 | **11.16배** |

새 FP64 비중·구간합은 이번에 직접 재측정했다. 표의 고정소수점 구간합은
직전 동일 조건 결과를 재사용했으며, 이번 이식 작업에서 fixed 전체 키생성
프로파일을 다시 실행했다고 주장하지 않는다. 단독 커널의 fixed 시간은 새로 측정했다.

이전/현재 FP64의 100개 키 구간합 차이는 512에서 -1 cycle, 1024에서 +3 cycles다.
성능 개선으로 해석할 차이가 아니다. 타이머 비용은 빼지 않았으며 빈 계측
13 cycles × 호출 수는 전체 계측 합의 약 0.11%다. 이 수치는 레지스터 압박·배치
영향을 포함한 완전한 overhead 보정이 아니다.

**이 구간합을 전체 키생성이 11배 느리다는 뜻으로 해석하면 안 된다.**
이번에는 비계측 전체 키생성 사이클을 새로 측정하지 않았다.

## 5. 아직 남아 있는 문제

- 하드웨어 FP64 명령을 실제 사용하며 `__aeabi_d*` 소프트웨어 double helper는 없다.
  그럼에도 원본 수치 규칙을 맞추는 보정 비용이 크다.
- 산술 경계값 반례는 그대로다. `(1+2^-32)*(1-2^-32)` 이후의 절삭·반올림에서
  원본과 다른 결과가 존재한다. 위 KAT 통과는 전체 산술 bit-exact 증명이 아니다.
- 입력 의존 시간도 남아 있다. n=256 후보 FFT의 zero/unit/tiny 입력 시간은
  각각 909,924 / 940,388 / 918,652 cycles이며 fixed는 세 경우 모두 55,864다.
- 이번 결과는 소스 이식·기능·커널/프로파일의 재현 확인이다.
  전체 상수시간·전력/EM 안전성이나 배포 적합성을 인증하지 않는다.

## 8. 추가 측정: 후보 검사에 있는 네 FFT 영역 함수

현재 소스의 `check_ortho_norm()`을 별도로 계측했다. 이 네 함수는
**NTRU solve 밖의 후보 직교노름 검사**에서 사용하는 고정소수점 연산이다.
아래 분모는 **전체 키생성**이며, 7절 NTRU 내부 비중과 직접 합산하지 않는다.

| 함수 | 키생성 전체 대비 512 | 키생성 전체 대비 1024 |
|---|---:|---:|
| `vect_invnorm_fft()` | 2.5456% | 3.2032% |
| `vect_adj_fft()` | 0.0257% | 0.0321% |
| `vect_mul_selfadj_fft()` | 0.0706% | 0.0886% |
| `vect_mul_realconst()` | 0.0790% | 0.0992% |
| **네 함수 합계** | **2.7210%** | **3.4231%** |

키 크기별 100개 동일 seed, 모든 후보 재시도를 포함한다. 직교노름 검사 호출은
680/1,523회이며, 그 검사 전체는 키생성 전체의 **5.7905%/7.6998%**다.
검사 내부만 100%로 보면 네 함수 합은 **46.9905%/44.4573%**다.
특히 역수 계산 `vect_invnorm_fft()`가 대부분을 차지한다.

상세·최소계측 대조·상세 반복 모두 키 KAT 200/200·NTRU 식·TCM/ECC 검사 PASS.
상세 두 실행은 함수별·키생성 전체 사이클이 전부 동일했다.
대조와 상세의 전체 키생성 시간 차이는 +0.0270%/+0.0137%로 관측됐다.
암호 소스 31개는 원본과 동일하며 계측 비용은 차감하지 않았다.
