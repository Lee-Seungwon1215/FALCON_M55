# FFT·iFFT·invnorm 커널 재측정 (2026-09-27)

## 조건

현재 `4.1_ntrusolve`를 `M55_ref`와 함수 단위로 재비교했다.
이번 재측정에서 암호 구현·컴파일 옵션·측정 프로그램은 변경하지 않았다.
기준 `kgen_fxp.c`는 `M55_ref`와 `ntt_opt`가 동일하며,
같은 ELF의 `ref_fxp.c`는 원본 본문에 이름만 변경한 oracle임을 다시 검증했다.

- 실제 NUCLEO-N657X0-Q / M55, 800 MHz, cache OFF.
- 코드 ITCM / 데이터·상수·스택 DTCM, 각각 256 KiB.
- GCC 15.2.1, -O3, fpv5-d16, fast-math OFF, 자동 FMA 결합 OFF.
- 같은 입력 스트림, 10 warmup +100회 / 크기·함수·backend.
- 보드를 다시 실행하여 **3회 반복**. 아래 값은 300회 호출의 평균 cycles.
  동일 100개 입력을 반복했으며 서로 다른 300개 입력이라는 뜻은 아니다.
- DWT CYCCNT, IRQ OFF. **Q32↔2×FP32 변환 포함**.
  입력 생성·복사·참조 결과 생성·오차 검사는 측정에서 제외.
- 시간 감소율 = `100 × (1 - 새 cycles / 원본 cycles)`. 음수는 느려짐.
- 세 실행의 소스·ELF hash 동일, raw hash·정상 종료·TCM/ECC/fault 검사 통과.

FFT는 느린 MVE 후보를 기본 경로에 넣지 않아 원본 고정소수점이며 0%다.
iFFT는 공개 함수의 크기 선택 분기까지 포함한다.
invnorm은 `fndsa_vect_invnorm_fp64_q32()` 직접 호출이며 공개 함수의 e 분기는 제외한다.
산술은 원본 Q32 제곱합 + FP64 나눗셈이다.
동일 구현의 별칭을 독립적인 다섯 커널로 중복 집계하지 않는다.

## 수치·시간 검사의 범위

- 큰 iFFT: 원본 대비 최대 4 Q32 LSB 차이(약 9.313e-10).
- 미채택 큰 MVE FFT: 512 최대 139 LSB, 1024 최대 264 LSB.
- 현재 FFT와 invnorm: 시험한 커널 출력은 원본과 일치.
- 부가 시간 검사: logn=4..10, FFT/iFFT/invnorm, 8개 입력군 ×100회씩 / 실행.
  세 실행 각각에서 동일 크기·연산의 입력군 sample 범위 최대 1 cycle,
  입력군 평균 범위 최대 0.01 cycle.
- 이번에는 전체 키생성·서명 KAT를 보드에서 새로 실행하지 않았다.
  이전 최종 소스의 KAT 300/300, 서명 KAT·검증·변조 거부 90/90 기록은 [result.md](result.md)에 있다.
  분석 시 기존 기록과 현재 소스의 일치도 다시 확인했다.
- 이 유한 시험은 모든 입력의 KAT 동등성·전체 상수시간 증명이 아니다.
- 전체 키생성의 invnorm/iFFT 기여도를 분리하는 ablation 실험과도 다르다.
