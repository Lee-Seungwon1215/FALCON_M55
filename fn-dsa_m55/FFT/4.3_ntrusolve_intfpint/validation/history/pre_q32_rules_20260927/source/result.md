# C 독립 구현 결과 — 정수 → 2×FP32 → 정수

2026-09-27. **실험 구현은 완료했으나 원본 KAT 6건이 달라 최종 ref로 채택할 수 없는 상태입니다.** 원본 기대값 변경, 실패 seed 우회, 숨긴 원본 fallback은 없습니다.

## 구현 범위

`ntt_opt` 복사본에서 독립적으로 시작했습니다. B의 소스를 읽거나 가져오지 않았습니다. 두 NTRU solve 구간의 `logn >= 4`에 연속 DS(2×FP32) 표현을 적용했고, 작은 크기는 원본 고정소수점으로 유지했습니다. NTT/CRT/Bezout/정수 갱신 및 서명·검증은 변경하지 않았습니다.

- 입력: 원본과 같은 비밀 스케일의 고정 길이 limb 스캔/마스크, 부호 확장과 비트 선택 → 직접 hi/lo FP32 생성.
- FFT/iFFT: 로컬 MVE FP32 어셈블리, 사전 변환 회전상수, iFFT 마지막 스케일링.
- 주변 산술: scalar FP32 + FMA 잔차 보정, 정규화된 나눗셈 seed 1회 + 고정 2회 보정.
- 출력: 중간 Q32 배열을 만들지 않고 직접 정수 `k`. 두 단계 반올림 경계 규칙은 유지.
- 공통 invnorm: 이전에 채택한 Q32 제곱합 + FP64 나눗셈을 동일하게 반영.
- 공개 FFT/iFFT 함수는 원본 그대로이며, NTRU 전용 내부 호출만 DS를 사용합니다.

## 측정 조건

NUCLEO-N657X0-Q, M55 800 MHz, 코드 ITCM/데이터·상수·스택 DTCM, 각각 256 KiB, 캐시 OFF, ECC 상태 확인. GCC 15.2.1 `-O3 -mcpu=cortex-m55 -mfpu=fpv5-d16 -ffp-contract=off -fno-fast-math`. M4 공통 어셈블리와 기존 M55 NTT 어셈블리 ON.

커널·합성 구간은 동일 ELF에서 원본과 C를 비교하고, 동일한 RNG 입력, warm-up 10회 + 측정 100회, DWT/IRQ OFF입니다. 전체 키생성은 원본 KAT의 동일 100 seed/크기, warm-up 3회, SysTick 64-bit/IRQ ON입니다. 서로 다른 B/C 개별 커널 프로그램을 직접 비교한 표는 아닙니다.

이 FFT/iFFT는 **연속 DS 배열에 대한 내부 커널**이므로 경계 변환은 포함하지 않습니다. 대신 입력 생성·최종 반올림을 별도 행으로 측정하고 아래 연결 구간에는 모두 포함했습니다. 따라서 기존 `4.1`의 Q32 공개 경계 커널과 숫자를 그대로 비교하면 안 됩니다.

직접 입력은 Q32 입력 생성보다 약 2배 느리고, checked 직접 정수 반올림은 원본 단순 정수 덧셈/shift보다 약 15.5배 느립니다. 점별 복소곱도 약 36.7% 느립니다. 반면 내부 FFT/iFFT와 특히 복소 역수 연산에는 큰 이득이 있습니다. 모든 함수가 빨라진 것은 아닙니다.

## 정확성/오차/상수시간

- 최종 키생성 KAT **294/300 일치**, 300/300 원본 정수 NTRU 방정식 통과.
- 불일치: 512 `test58,test78`; 1024 `test7,test65,test79,test80`.
- 입력 경계 host 검사: **1,846,200 계수 차이 0**.
- 양·음수 반정수 주변 host 검사: **589,968 출력 차이 0**; NaN/Inf/범위 초과 5종 명시적 거부. UBSan/float-cast-overflow clean.
- M55 직접 반올림 경계 검사: **18,576 출력 차이 0**.
- 합성 연결 구간의 100개 입력/크기에서 정수 k 차이 0. 그러나 위 실제 KAT 반례가 있으므로 일반 동등성 증명이 아닙니다.
- FFT 차이 최대 512 **77 Q32 LSB**, 1024 **141 Q32 LSB** (ceil); iFFT는 둘 다 **5 Q32 LSB**. DS 결과와 원본 Q32 결과의 실수값을 비교했습니다.
- 6 입력 종류 × logn 4~10 ×100회 연결 구간 시간: 시험한 클래스 평균/최소/최대 동일. 전체 상수시간 증명이나 전력/EM 검사는 아닙니다.
- 정수 변환에서 발견한 half 경계 잔차 손실은 TwoSum으로 수정했고, `&&`가 만든 비밀 조건 분기는 bitwise 마스크로 제거했습니다.
- 정규화 나눗셈의 유효 범위는 실제 NTRU의 유한·normal·제한된 크기 입력입니다. 모든 FP32 입력 범위에 대한 구현이 아닙니다.

## 실제 반례 단계 진단

[실제 입력 진단 로그](validation/results/fixtures/20260927T061058Z/raw.log), errors=[].

과거에 보관한 실제 f/F 입력 6개를 C 직접 입력 경로로 넣었습니다. 모든 입력 단계 차이는 0입니다. 다음은 최종 정수 k가 원본과 다른 계수 수입니다.

| 보관 입력 | 0: 연속 DS | 1: FFT 값만 원본 주입 | 2: FFT·역수까지 원본 주입 | 3: 점곱까지 원본 주입 |
|---|---:|---:|---:|---:|
| 1024-test7 | 30 | 30 | 0 | 0 |
| 1024-test74 | 12 | 12 | 0 | 0 |
| 1024-test79 | 15 | 15 | 0 | 0 |
| 1024-test80 | 9 | 9 | 0 | 0 |
| 512-test78 | 1 | 1 | 0 | 0 |
| residual-512-test58 | 64 | 63 | 63 | 0 |

첫 다섯 입력은 FFT 값만 동일하게 만들어도 차이가 남고 **역수 값까지 원본과 동일하게 만들면** k 차이가 사라졌습니다. 마지막 입력은 **점곱 값까지 원본과 동일하게 만들어야** 차이가 사라졌습니다. 따라서 이 진단 범위에서는 단순 정수↔DS 경계가 아니라 역수의 원본 Q32 계산 규칙, 추가로 점곱의 Q32 wrap 규칙 차이가 문제를 일으킵니다. 점곱 오차가 uint64 범위를 넘는 2개 값은 진단에서도 안전하게 포화 표시했습니다.

이것은 과거의 특정 반복에서 보관한 입력입니다. 예를 들어 `test74`의 보관 반복에서 k가 달라도 현재 전체 test74 키생성 KAT는 일치할 수 있습니다. **현재 실패한 1024-test65의 최초 차이 반복을 직접 캡처하지 않았습니다.** 위 6개 표는 현재 300건 키생성 전체의 모든 최초 차이를 추적한 결과가 아니며, 전체 해결 증명도 아닙니다.

원본 값 주입은 **원인 확인용 진단 펌웨어에만** 있습니다. 실제 암호 경로에는 주입·fallback이 없으며 KAT 불일치 상태를 그대로 공개했습니다.

## 결론

- B에서 파생하지 않은 C 독립 구현·빌드·M55 측정·오차/원본 KAT/서명검증/유한 타이밍 검사를 완료했습니다.
- 중간 Q32 배열을 없애면 내부 FFT/iFFT와 연결 근사 구간은 빨라질 수 있음을 측정했습니다.
- **원본 KAT 6건 불일치를 해결하지 못했으므로 통합 ref에 채택하면 안 됩니다.**
- 다음 정밀 작업은 DS 내부에서 필요한 원본 Q32 역수·wrap 규칙을 어떻게 보존할지 설계하는 것입니다. 어떤 원본 규칙을 보존할지 결정하지 않고 기대값을 변경해서는 안 됩니다.
- 기존 `ntt_opt`, `M55_ref`, B 소스는 이 C 구현 작업으로 수정하지 않았습니다.
