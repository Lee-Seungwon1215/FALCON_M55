# C: 연속 2×FP32 + Q32 계산 규칙 보정

2026-09-27: 중간 작업 배열을 FP32로 유지한 채 주변 산술의 Q32 호환 규칙을 추가했다.
**최종 M55 원본 키생성 KAT 300/300, 추가 독립 입력 300/300, 서명 KAT·검증·변조 거부 90/90 통과.**
그러나 모든 입력의 동등성이나 전체 상수시간을 증명한 것은 아니며,
전체 키생성은 기존 기준보다 느려졌다. **성능 채택판이 아닌 검증용 후보**다.
[현재 결과](result.md), [구현 원리·한계](../4.2_4.3_q32_rules_notes.md)를 먼저 참조한다.

## 경로

정수 → 직접 `2×FP32` → 직접 정수 k

- 대상: `solve_NTRU_intermediate()`와 `solve_NTRU_depth0()`의 공개 크기 `logn>=4` 근사 계산.
- FFT → 역수/점별곱/나눗셈 → iFFT 사이 배열은 계속 DS(hi+lo float)다.
- 실수값 하나가 float 2개, 복소수 하나는 실수부 2개 + 허수부 2개다.
- `logn<4`는 원래 고정소수점 경로. 키 후보 검사에는 기존 공통 invnorm 개선을 유지한다.
- NTT·CRT·Bezout·정수 다항식 갱신·서명·검증 알고리즘은 기존 코드다.
- 4.1처럼 FFT 사이마다 Q32 다항식 배열로 복귀한 구현이 아니다.
- 다른 후보의 암호 소스를 include/링크하지 않는 독립 폴더다.

## FP32 유지의 정확한 의미

곱셈/FMA·TwoSum과 작업 배열은 FP32다. Q32 절삭·modulo wrap·곱셈 하위 비트에는
일시적인 정수 값을 사용하고, 큰 곱의 carry 보정에는 원본 정수 곱셈도 계산한다.
나눗셈은 로컬 `inner_fxr_div()`의 원본 고정 반복 정수 규칙을 사용한다.
따라서 **모든 연산을 FP32만으로 구현했다고 주장하지 않는다.**
원본 재실행, seed별 예외, 다른 solver fallback은 없다.

원본의 raw-zero 분모 처리도 따르므로, 이전 문서의 “분모 0이면 새로 거부” 설명은
현재 구현에 적용되지 않는다. 기존 최종 출력 범위·유한성 검사는 유지한다.
